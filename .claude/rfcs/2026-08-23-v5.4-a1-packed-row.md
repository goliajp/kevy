# RFC — v5.4 A1: the packed row

Sub-RFC of `.claude/rfcs/2026-08-23-v5.4-use-the-declaration.md`, whose §8
requires this one before Axis A is implemented: a storage-format section, a
migration story, and a decision on whether the packed form is per-table
opt-in.

Status: **Phase A.** No implementation.

## 1. The term, measured three ways

| source | figure |
|---|---|
| source decomposition | a 7-field row costs 2,282 B for 435 B of values; 816 B of it is a 16-slot table holding 7 fields, 80 B an `Arc` header |
| process RSS, 50k rows | 1,699 / 1,694 / 1,713 B per row at 3 / 7 / 12 columns — **flat in the column count** (`bench/FINDING-2026-08-23-a-rows-fixed-cost-is-independent-of-its-columns.md`) |
| allocation arithmetic | table 816 + `ArcInner`+map 80 + value chunk 416 = 1,312 B against a packed 496 B |

The three agree, and the RSS measurement is the load-bearing one because it
is taken from outside the process and does not depend on the accounting the
decomposition corrected. **A row's fixed cost does not depend on how many
columns it has**, which is the signature of a fixed-size table, and it is
the thing this RFC removes.

## 2. The cheap version does not exist — measured, not argued

The obvious small change is to size the value table to the field count
instead of the `MIN_CAP = 16` floor. It does not work: with `MIN_CAP`
lowered to 4, `kevy-map`'s own suite fails
(`capacity_grows_doubling_from_min_cap`, `iter_yields_all_entries`,
`clear_drops_entries_and_resets_len`, `drop_runs_for_remaining_entries`).

The floor is load-bearing for the metadata mirror: `set_meta` writes at
`((i - GROUP_WIDTH) & mask) + GROUP_WIDTH`, and below one group width the
mirror lands inside the buffer but outside the real slot range, where a
group scan will read it as a live slot.

So the saving is only reachable by not having a per-row table at all. That
is what makes A1 a representation change rather than a parameter change.

## 3. The representation

A declared row becomes **one allocation**: the column values in declared
order, preceded by a small offset table.

```
[ncol u16][off_1 u16] … [off_n u16][value bytes …]
```

- Column order comes from the declaration, so **no field names are stored**.
- An absent column is an offset equal to its successor's — zero length,
  distinguishable from an empty value only if we spend a bit; the design
  keeps a presence bitmap instead, which also answers `HEXISTS` without a
  scan.
- `u16` offsets cap a packed row at 64 KiB of values. Past that the row
  keeps today's representation — a size class, not a failure.

Allocation arithmetic, glibc chunking, against today:

| columns | payload | packed chunk | today (table + Arc + value) |
|---:|---:|---:|---:|
| 3 | 423 B | 448 | 1,312 |
| 7 | 463 B | 496 | 1,312 |
| 12 | 514 B | 560 | 1,312 |

Row overhead above payload, including the keyspace slot: **1,002 B → 186 B**.

## 4. The ceiling, stated structurally

A packed declared row costs exactly:

| term | scales with |
|---|---|
| keyspace slot (key cell + `Entry` + control byte, amortised) | rows |
| offset table | columns |
| value bytes | payload |
| one allocator chunk header and its rounding | rows |

**No term remains that the declaration could have removed, and no term is
constant in the column count.** The second half is the real statement: the
defect being removed is not that the overhead is large but that it is *flat*.

## 5. What it must not break

- **The wire.** `HGET`/`HSET`/`HDEL`/`HGETALL`/`HRANDFIELD`/`HSCAN` and the
  field-TTL verbs answer identically. A packed row is a storage form, not a
  type.
- **Undeclared hashes.** A hash on a key outside every declared prefix keeps
  today's representation. The packed form is **earned by the declaration**.
- **Field-level TTL.** `hfttl` is keyed by (key, field name); a packed row
  has no field names, so the sidecar must map to column index, and expiry
  must clear the presence bit rather than remove a map entry.
- **`SmallHashData`.** The 22-byte inline form still wins for tiny hashes
  and stays in front of the packed form.
- **Every consumer of the value bytes**: `tier_codec::encode`
  (`crates/kevy-store/src/tier_codec.rs:24-47`), the snapshot payload
  encoder, `dump_aof`'s `HSET key f v …` re-emission
  (`crates/kevy-persist/src/rewrite_fmt.rs:208-218`), and the embedded
  dispatcher's hash ops.

## 5b. The write path, and why it is the hard half

Reads were the easy half: a packed row answers them from bytes it already
has. A write has to change the row, and the packed form has no free slot to
change — the values are contiguous.

Four strategies, costed before writing any of them:

| | what it does | what it costs |
|---|---|---|
| 1 | fall back to the general hash on first write | the memory saving is gone after one write; on a workload that updates rows repeatedly it is zero |
| 2 | rebuild the buffer on every write | a single-field update copies the whole row — 463 B for the measured shape, against a hash lookup and an in-place `SmallBytes` swap |
| 3 | keep tail slack so a same-length update fits | reintroduces a fixed overhead, which is the thing this type deletes |
| 4 | in place when the new value is the same length, rebuild otherwise | no fixed overhead; the fast path is opportunistic |

**Strategy 4**, with one caveat that matters more than the choice.

The fast path only helps when updates are same-length, and **that is a
property of the column, not of rows in general**:

| column | update | same length? |
|---|---|---|
| unix-ms timestamp | 13 digits for the next century | essentially always |
| fixed-width id | — | always |
| i64 counter / age | 18 → 77, but 999 → 1000 | usually, until it crosses a digit |
| enum / status | `live` → `paused` | often not |
| free text, float | — | usually not |

The declaration carries types (`COLUMN age i64`), but **a type does not fix a
width** — an i64's decimal form is variable. So the in-place path is an
opportunistic fast path layered on a correct rebuild, never a property the
design may assume.

**And a warning against the shape of this reasoning.** The benchmark's write
is `HSET row:i age <two digits>`, which is same-length almost always. Picking
strategy 4 *because* that is the benchmark's shape would be optimising for
the benchmark rather than the engine. It is chosen because it adds no fixed
overhead — strategy 3's disqualification — and its fast path is a bonus that
must be measured separately from the memory term, not folded into it.

**Measurement obligation.** The memory saving and the write throughput are
reported separately, and the write column is the one at risk: writes are
where kevy leads PostgreSQL by the widest margin today (28× at `everysec`).
A memory win that costs a third of the write throughput is a trade for the
owner to make, not a result to bank.

## 6. Migration

**There is no on-disk migration**, and that is the point of sequencing A1
before Axis D: the AOF is a command log, not a heap image. A packed row is
built by replaying the same `HSET` frames a 5.3 log already contains, and a
5.3 binary reading a 5.4 log sees the same frames. The format version does
not move.

Snapshots do carry payloads, so `snapshot_payload` must either emit the
existing shape from a packed row (cheap, keeps `KEVYSNAP` unchanged) or gain
a version. **This RFC proposes the former** — no new snapshot version for a
representation that is not visible on the wire.

## 7. Opt-in

**Not per-table opt-in.** A declared table's rows take the packed form
automatically; there is no knob. The reasoning: a knob here would be a
performance switch whose wrong setting is invisible, and the fallback for
the cases the form cannot serve (over 64 KiB of values, undeclared keys) is
already automatic and per-row. A deployment that needs 5.3 behaviour runs
5.3.

## 8. Sequencing inside A1

1. **The packed value type and its accessors**, behind the existing `Value`
   enum, with the hash ops able to read it. Nothing writes it yet.
2. **Write path**: a declared row's `HSET` builds the packed form. Gated so
   it can be turned off in one place while measuring.
3. **The consumers** in §5 — tier codec, snapshot, rewrite, embedded.
4. **Field TTL by column index.**
5. Measure against the 5.4 baseline; revert the whole thing if the RSS term
   does not move, on the Axis B precedent.

## 9. Open

- The presence bitmap costs `ceil(ncol/8)` bytes and buys `HEXISTS` without
  a scan; whether that is worth it against an offset-equality convention is
  not decided here.
- `MIN_CAP`'s justification — "one SSE2 group so the future SIMD path can
  run a full group scan unconditionally" — describes a path that does not
  exist. Whether the keyspace map should keep paying for it is a separate
  question this RFC does not open.
- A2 (index entries by dense row id) is **not** in this RFC. It is the other
  24.6%, and it depends on rows having a stable dense identifier, which A1
  does not create.

## 10. Amendments from implementation (2026-08-23)

Phase B changed four things this RFC decided in Phase A. Each is recorded
here rather than left to the commit log, because each was decided wrongly
first.

### 10.1 The form has to be reachable, not just correct (§8 step 2)

§8 sequenced the write path as "a declared row's `HSET` builds the packed
form". That is necessary and not sufficient: the write hook only ever sees
rows written **after** their table existed. Three ordinary sequences leave
rows behind it —

1. `TABLE.DECLARE` over an existing keyspace;
2. restore from a snapshot, whose loader installs rows through
   `Store::load_hash` without going through the dispatcher (AOF replay does
   go through it, and packs);
3. a row nothing writes again.

Measured consequence: on the box, two million rows, the flag moved RSS by
nine bytes per CSV-MB, because `bench/pgcompare.py` declares the table after
loading and not one row was converted
(`bench/FINDING-2026-08-23-a-declaration-does-not-reach-the-rows-that-preceded-it.md`).

**A declaration backfills**, in the shape the index backfill already uses:
keys collected per shard when the table-catalog generation moves, 2,048
converted per tick. The table catalog grew a generation for it.

### 10.2 Mutation goes through one conversion, not through each verb (§5b)

§5b costed four write strategies and chose #4 for `HSET`. It said nothing
about the other mutating verbs, and they were left matching on the general
forms only: `HDEL` and `HINCRBYFLOAT` answered WRONGTYPE about a row the
server was holding, and the field-TTL reaper deletes through `HDEL` and
drops the result, so an expired field on a packed row stayed readable for as
long as the row lived.

`Store::unpack_row` now runs in front of any mutation that is not the packed
form's own fast path. The general arms are then correct for every mutating
verb including ones not written yet, and the write hook packs the row again
afterwards. §5b's strategy 4 still governs `HSET`, which is the verb the
fast path was costed for.

### 10.3 The form is a hash everywhere the type is asked about (§5)

Nine paths outside the read and write lanes decided what to do by matching
on the form: the tier codec, the demotion sampler, the segment window's
hot/cold classification, segment-row encoding, the peek lanes, and the
field-TTL precheck. A packed row reached all nine and was excluded from
tiering entirely — the memory representation could not use the other memory
mechanism.

The tier codec keeps `COLD_TAG_HASH` for a packed row rather than taking a
new tag: **the tag answers `TYPE` and gates the WRONGTYPE precheck, and both
are about the type, which has not changed**. Which form to rebuild is a
property of the payload, and rides in the high bit of its field count. Every
`type_tag == COLD_TAG_HASH` site stays correct as written, and there are
more of those than there are decode sites.

### 10.4 There is a switch, and §7 needs re-reading because of it

§7 decided against a **per-table** knob and that stands. But `packed-rows`
exists as a server-level setting, default off, settable through `CONFIG SET`.
It is not a per-table performance switch; it is what lets the two
representations be compared on one running server rather than two builds —
and a replica has to store rows the way its primary does, or a failover
changes the memory profile.

**Open for the owner**: whether 5.4 ships with it defaulting on. §7's
reasoning ("a deployment that needs 5.3 behaviour runs 5.3") argues on;
default-off means the release ships the feature dormant. The measurement
decides what the trade actually is, and the trade is the owner's to make.

### 10.5 What the catch-alls cost, as a process note

The same defect landed three times in two days — reads, then the memory
paths, then the mutating verbs — and each time it was found by reading code
looking for `Value::Hash`, which found a different subset every time. A
match that ends in a catch-all does not mention the form it is getting
wrong, so there is nothing to grep for at the site of the defect.

`bench/formgate.sh` now does that search mechanically: every public hash
verb must be exercised against a packed row in the parity suite, or say
where it is covered instead. It cannot prove a verb is correct on a packed
row; it proves nobody added one without deciding.
