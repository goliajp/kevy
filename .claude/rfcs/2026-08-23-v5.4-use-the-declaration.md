# RFC — v5.4: use the declaration

Owner directive (2026-08-23): 以 perf / mem / disk 都大幅改善为目标设计与研发 5.4.

Status: **Phase A, design round.** Acceptance lines are structural
statements about which terms remain and how each scales. No ratio against
PostgreSQL is an acceptance line anywhere in this document, and none may
become one (`feedback-design-from-own-model-not-attack`).

## 1. One observation, three media

`TABLE.DECLARE` enumerates a table's columns, their types and every index.
The declaration is **complete** — the whole scope boundary rests on that
(`.claude/plans/2026-07-03-rds-refugee-services.md`, Law 3) — and it is
**persisted** (`crates/kevy/src/cmd_table.rs:42-46`).

Three independent decompositions, taken 2026-08-22/23, each reconciled
against a measurement, all land on the same sentence: **the engine was told
the schema and then stores, logs and serves as though it had not been.**

| medium | what is re-stated per unit | measured cost |
|---|---|---|
| memory | a 16-slot hash table per row, answering "which field is `dept`"; seven field names inline in every row | ~62% of a declared row's 2,280 B footprint |
| disk | every field name re-serialized into every AOF record, wrapped in RESP framing on a file nobody parses as RESP | 148 B of overhead on a 585 B record; 63 B of it is names |
| reads | `FIELDS` probes the keyspace even when the index already stores every requested column | up to 320 row reads per list page, ~300 discarded |

Each decomposition closes on its measurement without a fudge term:

- memory: Σ = 2,280 B/row against a measured 5,501 KB/CSV-MB (±4%)
- disk: Σ = 585 B/record → 1,349 KB/MB against a measured **1,348**; at
  4 KB rows 1,060 against a measured **1,060**
- the list page's four terms were named, two were attacked, and the attack
  measured +93% throughput (`bench/FINDING-2026-08-23-*.md`)

That is the thesis of 5.4. Not three optimisations — **one representation
decision, applied in the three places the declaration is currently
ignored.**

## 2. What the disk decomposition established

Worth stating separately because it removes three candidate explanations:

- **The untiered disk number *is* the AOF record format.** Indexes are
  never persisted — declarations go to a text sidecar and every index is
  rebuilt from the keyspace at boot
  (`crates/kevy-index/src/catalog_sidecar.rs:70-72`). Snapshots are never
  written automatically; `PersistenceSection`
  (`crates/kevy-config/src/schema.rs:47-73`) has no `save` directive at
  all. The feed is a RAM ring with two tiny sidecars. Nothing else
  contributes.
- **AOF rewrite does not compact a row workload.** `dump_aof` re-emits a
  hash as `HSET key f v f v …` — byte-for-byte the shape the client sent
  (`crates/kevy-persist/src/rewrite_fmt.rs:208-218`). It reclaims only
  superseded records; for insert-only ingest the output equals the input,
  at 1 byte written per live byte per cycle.
- **A compact binary encoding already exists in the tree and is unused for
  this.** The snapshot format has no RESP framing, no verb, no `\r\n`, and
  u32 lengths instead of ASCII decimal
  (`crates/kevy-persist/src/snapshot_fmt.rs:18-56`). It is strictly smaller
  than the AOF form and only ever runs on an explicit `SAVE`.

## 3. Axis D — the record format

### The terms, per record, for a 7-field row with a 400 B value

| term | bytes | structural? |
|---|---:|---|
| user values | 437 | — |
| envelope: length + CRC32C | 8 | structural (integrity) |
| key + framing | 17 | structural (the log is keyed) |
| **field names + their framing** | **63** | incidental — the schema is declared |
| **RESP array header, verb, value framing** | **60** | incidental — the envelope already carries an exact length |
| **record** | **585** | = 1.32 × the CSV line |

### The shape this points at

A record for a **declared** table is: envelope, key, a table/schema
identifier, and the column values with binary lengths — in declared column
order, with absent columns marked by a bitmap rather than named.

This is what the snapshot encoder already does for payloads
(`snapshot_payload.rs`), so the release is not inventing an encoding; it is
using the one the repository already trusts, on the path that currently
does not.

Non-declared keys keep the verbatim-RESP record unchanged. The compact form
is **earned by the declaration**, exactly as in Axis A.

### The ceiling, stated structurally

After the change a record decomposes into exactly:

| term | scales with |
|---|---|
| envelope (length + CRC) | records |
| key + its length | records × key width |
| schema id | records |
| column values + binary lengths | value bytes + columns |

**No term remains that the declaration could have removed.** For the
measured row that evaluates to ≈470 B against today's 585 — but the number
is a consequence of the four terms, and the design is right or wrong
according to whether a fifth survives.

### Correction, 2026-08-23: the ceiling above is too high

Recomputed term by term before implementing, which is the check Axis B
skipped. The ≈470 B figure assumed the compact record could be *table
shaped* — a table id plus column lengths. It cannot: an AOF record has to
represent an arbitrary argv, because the log carries every verb, not only
writes into declared tables. A general record keeps one length per argument.

Splitting the saving by what each half needs:

| change | needs | record | KB/CSV-MB | saving |
|---|---|---:|---:|---:|
| today | — | 582 B | 1342 | — |
| binary lengths instead of RESP framing | nothing | 546 B | 1259 | **6%** |
| …plus eliding declared field names | the write path to see the table catalog | 525 B | 1211 | 10% total |

And the second half is blocked by layering: the AOF append lives in
`kevy-rt` (`Shard::log_write`, `crates/kevy-rt/src/exec.rs:322`) while the
table catalog lives in `kevy` above it. Reaching it means a new question on
the `Commands` trait — a real interface change, for 3.6 percentage points.

At 4 KB rows the whole thing is worth 2.2%: the payload dominates and the
framing barely registers.

**So Axis D is 6% for a format version, a migration, and changes to replay
and rewrite — against Axis A's memory term, which is 5,821 KB/CSV-MB
against PostgreSQL's 879.** The sequencing in §8 put D before A on the
grounds that D is self-contained. Self-contained is not the same as worth
doing first, and this arithmetic says A leads.

### Compatibility

The AOF already carries a format version in its magic (`KEVYAOF2\n`,
`crates/kevy-persist/src/record.rs:21`) and the repository has done a V1→V2
migration before. A V3 reader must replay V2 files unchanged; a V3 writer
must be refusable by config for a deployment that needs to roll back to a
5.3 binary. **A one-way format change is not acceptable and this RFC does
not propose one.**

## 4. Axis A — the row representation

Unchanged from `.claude/rfcs/2026-08-22-rds-side-representation-and-paths.md`
§3, restated here as a 5.4 deliverable: a declared row is a packed value
with a small offset table, and an index entry references it by a dense row
identifier rather than by the key bytes.

The ceiling stated there — keyspace slot, packed payload, index entry, and
nothing else — evaluates to ≈865 B against today's 2,280.

**Axis D and Axis A share the encoding.** A packed in-memory row and a
compact on-disk record are the same column-ordered layout in two places;
doing them together means one format decision, one migration story, and one
set of tests. Doing them apart means two.

## 5. Axis B — index-only reads

Two of the four list-page terms remain
(`bench/FINDING-2026-08-23-merge-the-pages-instead-of-sorting-them.md`):

- **Hydration runs per shard, before truncation.** Up to 320 row reads to
  return 20. Moving it after the merge costs 20. Needs the shard to send
  unhydrated rows and the origin to ask the winners' shards in a second
  phase — a protocol change, not a local edit.
- **`FIELDS` ignores the covering values the segment already holds**
  (`crates/kevy-index/src/segment.rs:92-107`) and probes the keyspace
  instead (`crates/kevy/src/cmd_index_query/wire.rs:107-117`). Those
  covering bytes are already paid for in Axis A's budget. Serving from them
  is an index-only scan, and `tablegate` L6/L7 already assert a row-read
  counter of zero for the clause path — the assertion exists, the `FIELDS`
  path just does not satisfy it.

The second is local and independently testable. The first is a design item
and is sequenced after it.

## 6. Axis C — the flush budget

Measured, and it bounds itself
(`bench/FINDING-2026-08-22-write-durability-is-a-flush-budget.md`): kevy
carries **4.72 writes per flush** and issues 1,549 flushes/s against a
device that does 1,212/s bare; PostgreSQL carries 38.5 and uses 749/s.

The acceptance line for this axis is **writes per flush**, measured at
4.72. The flush budget is already spent, so the gain must come from
carrying more per flush, which the current mechanism cannot do by
construction: the group-commit bracket's unit is one socket read of one
connection (`crates/kevy-rt/src/inbox.rs:86-89`), and in lane mode the
sharing that occurs is an accident of the one-fsync-in-flight gate
(`crates/kevy-rt/src/aof_writer.rs:252-277`).

**This axis is admitted to 5.4 only if Axes D and A leave room.** It is the
one whose mechanism reaches furthest into the reactor, and unlike the
others it has no version-gated fallback: a commit window changes when a
reply is released, which is observable behaviour under crash.

A separable defect ships regardless: **p99 at one client is 50,304 µs,
which is exactly `park_timeout_ms`'s default**
(`crates/kevy-rt/src/shard.rs:313-317`). The reply is held behind a durable
watermark and released by a best-effort wake
(`crates/kevy-rt/src/aof_writer.rs:139-141`); a missed wake costs a full
park. That is a scheduling cost wearing a durability number's clothes, and
it is a bug, not a design item.

## 7. What 5.4 refuses

- No planner, no cost model, no automatic access-path selection. The
  declaration still chooses the path; 5.4 only stops ignoring it.
- **No wire change.** Every verb keeps its RESP surface. The compact
  encodings are internal to storage and the log.
- **No one-way format migration.** A 5.4 writer must be configurable to
  emit the 5.3 record format, and a 5.4 reader must replay 5.3 files.
- The undeclared-key path keeps every representation it has today. Compact
  forms are earned by a declaration, never imposed.
- "Beat PostgreSQL on X" is not an acceptance line in this release.

## 8. Sequencing, and why this order

1. **Baseline.** Three axes, fixed reference, on `develop` as it stands.
   Running.
2. ~~**Axis B second half** — `FIELDS` from covering values.~~ **Done, and
   reverted: it moves nothing measurable.**
   `bench/FINDING-2026-08-23-index-only-fields-is-noise.md`. The reason
   generalises — `peek_hash_rows` coalesces a page's cold rows into ONE
   batched read, so the per-row cost this attacked was already amortised.
   The correctness bug the work uncovered (a covering copy outliving the
   field it copies) is fixed and stays.
3. **Axis A** — the packed row, promoted ahead of D. Memory is 5,821
   KB/CSV-MB against 879, and unlike Axis B's target nothing amortises a
   per-row representation cost.
4. **Axis D** — the record format, demoted. Worth 6% of the log without
   touching layering, 10% with; see the correction in §3. Self-contained,
   but small next to A.
5. **Axis B first half** — hydration after the merge. Protocol change;
   after A because A changes what a hydrated row costs.
6. **Axis C** — only if 2–5 leave room. The `park_timeout` defect is split
   out and fixed independently of that decision.

Each step is measured against the step-1 baseline before the next begins,
and a step that does not move its own term is reverted rather than
explained — the discipline that produced three refutations in the 5.3
measurement round (`kevy-alloc`, the cache-line hypothesis, and the
bimodal-tail attribution).

## 9. Open, and honestly open

- **The vlog stores field names and the key a second time**
  (`crates/kevy-store/src/tier_codec.rs:29-36`,
  `crates/kevy-vlog/src/lib.rs:345-346`). Axis D's encoding should serve
  both, but the vlog's key copy exists so compaction can ask whether a
  record is live (`crates/kevy-vlog/src/lib.rs:22-25`) — removing it needs
  a different liveness question, which this RFC has not designed.
- **The first 256 MiB of spill is compressed with an empty dictionary**
  (`crates/kevy-vlog/src/lib.rs:271`, trained only at rotation at `:294-304`),
  and the dictionary's reach is capped at 64 KiB by a 16-bit offset
  (`crates/kevy-compress/src/lib.rs:71`). Both are real, both are unmeasured
  in a deployment-shaped run, and neither is in scope until measured.
- **`SegRows` has dead-record accounting and no compactor**
  (`crates/kevy-store/src/segrows.rs:27,356-361`). Stranded records are
  permanent. Out of scope for 5.4 unless a measurement says otherwise.
- The intermittent `idx p99` spike that appears once in five passes on
  *every* arm including `develop` remains unexplained and unattributed.
