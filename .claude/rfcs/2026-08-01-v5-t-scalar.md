# T-scalar:scalar 索引冷段 —— 树前缀住进磁盘,查询照旧

> R2b/R2c 的实施 RFC(scalar 半)。范围 = **窗口列访问路径**的索引
> (单列 INDEX 或窗口列引导的 ORDERPATH):只有它们具备"树前缀 = 出窗批"
> 的性质,摘除 O(log)+O(批);其他索引的窗口语义随 T-row 的行出窗一并处理。

## 〇、一个上位拍板:scalar 冷段是 derived spill,不进真相集

R2b 的"段 = 持久真相"是对**行段**说的(行数据唯一副本)。scalar 索引段不同:
行仍在热层+AOF(T-scalar 阶段行不出窗),索引本来就是重启即全量 backfill 的
derived state。因此:

- **不用 SEGMENTED 帧**(那是行段的缝合);**不用 crash 矩阵**(重启自愈);
  墓碑只需内存形态(重启重建)。
- 重启 = 旧 scalar 段 manifest drop + sweep,backfill 重建,tick 滑动重新段化。
  重建成本与现状(全量 backfill)同阶。
- manifest 照用(目录 + sweep 语义),entry.meta 标 `derived:idx:<name>`,
  与未来行段(`row:<table>:<bucket>`)同居 `segs-<shard>/` 不混淆。
- 推论:backfill 可流式分流(<W 直接喂 SegBuilder 不进树),重建内存峰值
  可控 —— 记为 v-next,首版 backfill 照旧建满再滑。

## 一、摘除:`Segment::split_off_below`

`BTreeSet::split_off(&(W, vec![]))` 留 >=,换出 < —— O(log);换出批逐条
同步 back / value_counts / values(RowValues)并 **按现有 per-entry 路径
等式减账 stats**(entries/approx_bytes 漂移 = tier reserved floor 漂移,
单测钉账目恒等)。back 的冷条目**整体丢弃**(见 §四墓碑,不需要 old value)。

## 二、段 key 编码:`(IndexValue, row_key)` → 严格升序字节键

`seg_key = order_key(value) || frame(row_key)`。窗口列必 i64(WINDOW 验证
已保证)→ value 部分固定 8B;ORDERPATH 复合键已是序保字节串,直接用。
`frame(row_key)` = composite 的 escape(0x00→0x00FF)+ 0x0000 终止子,
**无 255 cap**(那是 composite 的选择,不是编码的);新 pub helper 进
kevy-index(`segkey.rs`),往返单测 + 与树序一致性 property 测试。
payload = VALUES 列的现编码(claused 冷路径备用;首版可空)。

## 三、W 维护与出窗步(tick 内,预算化)

- `ShardIndex.window: Option<WindowState { spec: WindowSpec, w: i64 }>`,
  refresh() 时从 table catalog 推(索引名 `<table>.<col>` ↔ spec 映射);
  catalog 无 table_gen —— per tick Arc 指针比较,不加锁账。
- tick:树尾 max(O(log))→ `W' = bucket_floor(max − span)`;`W' <= W` →
  一个比较即返(idle 恒零判据)。`W' > W`:split_off_below → 喂 SegBuilder
  (一批一段,meta 记 `[W, W')`)→ finish+fsync → manifest add(fsync)→
  内存段目录登记 → W = W'。
- 执行位:首版 shard tick 内直写(derived 段,丢了自愈;段小 —— 一桶的
  索引条目)。tick 卡顿实测超预算(perfgate)才移 persist worker,不预设。
- 预算:每 tick 最多摘 N=4096 条,未尽下 tick 续(W 推进推迟到批完成,
  中间态 = 树里仍有 <W' 条目,查询照走树,语义不变)。

## 四、正确性:冷条目的陈旧问题与 row_key 墓碑

行仍热,可被改写/删除/复活 —— 冷段条目会陈旧。解:

- 建段时顺手建 **per-index 冷 row bloom**(自写小 bloom,`kevy-index` 内,
  无依赖);段目录持 bloom + `tombs: HashSet<row_key>`。
- 行写/删路径(apply/remove):树 back 无命中 && bloom 命中 → `tombs.insert(row_key)`。
  假阳性 = 白加一条墓碑,无害。复活自动正确:新条目进热树,旧冷条目被墓碑遮蔽。
- 归并读:冷段命中 row_key ∈ tombs → 跳。墓碑量 ∝ 冷行写率(SME 低);
  compact(v-next)物理清。

## 五、查询归并(两 train)

- **T-scalar-a(本 RFC 首程)**:`count` 与无 FILTER `range` 的冷归并。
  seam 在引擎层调用点(kevy-index 拒 I/O 的铁律不破):server
  `query.rs:115/:119`,embedded `ops_index.rs:255/:264`。count = 树 count +
  Σ seg.count_range − 墓碑修正(墓碑在段区间内逐条判);range = 树页 +
  段 RangeIter 双源归并(值序,墓碑过滤),reduce 不变(本就多 chunk 归并)。
- **T-scalar-b**:claused 冷路径(段命中 → 行仍在热层 → peek 列完成
  FILTER/VALUES;或 payload 存 VALUES 直读)。b 落地前,claused 查询在
  **有冷段的索引**上具名拒绝(`ERR index '<name>' has cold segments;
  clauses land in the next train`)—— 静默少数据不可接受,拒绝可接受
  (窗口是显式声明的新功能,无存量破坏)。
- embedded 同轮镜像(oracle 比对);embedded 滑动 tick 挂 reaper
  (首个 index tick,探路已注明位置)。

## 六、gate

1. 无 WINDOW 表 byte-identical(现有全测 + oracle 即门)。
2. 窗口表语义等价:同数据两表(带窗/不带),count/range 全量对照 byte 等
   (含复活/删除/改写扰动后)。
3. idle:无出窗 tick = 1 比较(计数器断言);滑动稳态成本 ∝ 出窗条目率。
4. 内存真降:出窗后树 entries 下降断言 + `reserved_bytes` 同步下降。
5. KV/pubsub 赢线不碰(改动全在 index 面)。

## 七、发散区(本轮)

1. **backfill 流式分流**(<W 不进树直接进段)—— 重启内存峰值消失,v-next。
2. **段内 payload 存 VALUES** vs 回热层行取列:b train 实测选(冷查询频率
   低,回查省段体积;但回查绑行在热层的前提,T-row 后失效 —— 倾向 payload)。
3. **ORDERPATH 冷段做跨窗分页**:窗口列引导的复合索引冷段天然支持
   "翻到第 N 页历史"—— SME 报表场景的免费收益,b train 一并接。
