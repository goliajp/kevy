## The audit, first

| reported | verified in code | worse than reported? |
|---|---|---|
| F7 embedded can't reach TABLE types | `lib.rs:192-194` re-exports views+indexes, not tables | **yes** — embedded's `TableVerifyReport` is `(Vec<(Vec<u8>,[u64;6])>, [u64;2])`: anonymous arrays, no field names at all |
| F9 bad spec panics on boot | `ops_table.rs:44` calls `compile_table` **without ever calling `validate()`** — only the RESP path (`table_wire.rs:52`) validates | **yes** — two holes: 4.0.0's `validate()` lacked the ORDERPATH-column check (since added on develop), *and* the typed path skips validate entirely, so even today's develop panics from embedded |
| F16a tiering idle CPU fixed at ~18 % | `tier_tick` → `reserved_bytes` runs **every tick** and `DocBlobs::Many::approx_bytes` walks `m.values()` — a full traversal of text doc-blob maps 10×/s, plus fields/docvalues/positions equivalents | **yes** — the report guessed "per-tick key scan"; the dominant term is the per-tick full-stat walk of the *index* structures, which is why cost tracked index size, not demote work. Same disease as the rowvalues rescan fixed in `91c89e7b`, unfixed for text/ann/agg |
| F10 mixed counter semantics | `coerce_failures` read from `seg.stats()` (lifetime), `drift` recomputed — confirmed | as reported, root cause = the anonymous report type has nowhere to state semantics |

The unifying diagnosis, in one sentence each:

- **D1 — the typed facade is the untested twin.** The RESP face is
  exercised by every gate; the embedded face of the same feature can be
  missing types (F7), skip admission checks (F9), and expose unnamed
  tuples (F10's root) — and nothing in CI would know, because nothing
  links `kevy-embedded` from the position of an outside consumer.
- **D2 — admission is split across faces.** `validate()` names every
  refusal, but only one of the two doors calls it. Any invariant it
  fails to establish becomes a downstream `expect` — a panic on
  somebody's boot path.
- **D3 — periodic work lacks the idle-state discipline.** "Idempotent
  is not convergent": the tier tick's cost is a function of what exists
  (index size, key count), not of what needs to move. mailrs measured
  300–500× idle CPU and turned the flagship feature off.
- **D4 — reports mix time semantics silently and omit the counter that
  explains the surprise.** Fresh `drift` beside lifetime
  `coerce_failures`; a `duplicates` count whose pagination consequence
  is stated nowhere; composite over-length row *exclusion* that only
  shows up as an unexplained entries diff (cost mailrs a two-row hunt
  and then an outage-adjacent fix).
- **D5 — the migration knowledge exists only in mailrs's notebook.**
  Eight transferable lessons (single-valued-dimension question,
  membership rows, every-writer audit, backfill-from-union, shadow read
  incl. order, reader-then-writer deletion sweep, predicate ⇒ new
  ORDERPATH not duplicated column, declare-at-boot compare) — none in
  our docs. And the strongest pitch we have ever received — *"the
  engine maintaining the index is the only version that can be
  verified"*, with 89 %/76 % measured drift in hand-maintained indexes
  — is absent from `docs/tables.md`.

## The trains

### V1 — facade parity, enforced by a consumer gate (D1)

- Re-export `TableSpec` / `TableIndex` / `OrderPath` (+ anything else
  the audit sweep finds appearing in public signatures without a
  facade path) from `kevy-embedded`.
- Replace the anonymous verify tuple with a named struct
  (`TableVerify { per_index: Vec<IndexVerify>, .. }`, every field
  doc-commented with its time semantics). The old alias stays as a
  deprecated shim for 4.1 (semver).
- **facadegate**: a consumer crate *outside* the workspace (own
  lockfile, path deps only on `kevy-embedded` + `kevy-client`) that
  exercises every public family — KV, pubsub, durability knobs,
  indexes, views, text, tables (declare→write→query→verify), tiering
  config — using **only facade imports**. CI job builds and runs it.
  This is the gate that makes F7 structurally unrepeatable.

### V2 — one admission authority; declaration is panic-free (D2)

- `compile_table` takes the spec and **returns `Result`**, calling
  `validate()` itself — the invariant becomes impossible to bypass
  rather than documented in an `expect`. Both faces inherit it; the
  wire path's second validate costs microseconds.
- Sweep `kevy-index` for `expect`/`unwrap`/indexing on spec-derived
  data in the declare→compile path; each becomes a named refusal.
- New fuzz target `table_spec`: arbitrary bytes → wire parse →
  validate → compile → **must never panic** (Err always acceptable).
- Documented guarantee in `docs/tables.md`: `table_declare` returns
  errors; it does not panic, whatever the spec says.

### V3 — declare lifecycle for the boot pattern (D2 adjacent, F8.2)

Declaring at boot is the steady state, and today's API punishes it:
re-declare of an existing table is an error, so the obvious code keeps
running against the first boot's shape forever.

- `Store::table_ensure(spec) -> Ensure::{Created, Unchanged}` — equal
  spec is a no-op success; **different spec is a named error carrying
  the diff** (never a silent rebuild: a rebuild is a full backfill and
  must be asked for).
- `Store::table_replace(spec)` — explicit drop + declare + rebuild.
- RESP: `TABLE.ENSURE`, `TABLE.REPLACE`; oracle cases for both faces.
- `docs/tables.md` boot-pattern section written around `ensure`.

### V4 — VERIFY tells the truth in one time-frame (D4)

- Every number in the VERIFY report is **recomputed fresh per call**:
  `coerce_failures` (the name promises it), `drift`, `duplicates`, and
  **new: `excluded`** — rows the composite encoder dropped
  (`MAX_STR_COMPONENT` and any other exclusion), the counter that would
  have turned mailrs's two-row hunt into a named number.
- Lifetime counters remain where lifetimes belong (INFO/seg stats).
- Docs beside the ORDERPATH section: non-zero `duplicates` means the
  sort is not a total order and pagination will skip/repeat at
  boundaries; use a **bounded** final tie-break column (numeric or a
  hash — a raw Message-ID is the worked counter-example).

### V5 — tiering converges: idle must be nearly free (D3)

Two independent fixes, both required (either alone leaves a term):

- **Stats stop being walked.** `reserved_bytes` is served from a
  per-shard cache invalidated by an index-write generation counter —
  an idle store recomputes *nothing*. Under write load the walk is
  additionally bounded by making text/ann/agg `approx_bytes` running
  counters (the exact treatment `RowValues` got in `91c89e7b`),
  starting with the measured offenders (`DocBlobs::Many`,
  fields/docvalues/positions maps).
- **The sampler backs off.** A tick whose demote batch moves zero
  bytes doubles the tick's skip (to a ceiling ≈ 6 s); any demotion or
  used-memory growth past the watermark resets it. `effective_target
  == 0` (floor exceeds budget) enters the same idle path immediately —
  today it guarantees a scan per tick forever.
- **Gate**: tiergate line reproducing mailrs's measurement — server
  idle 30 s, tiering off vs on with converged data: on-CPU must be
  within a small multiple of off, not 300×.
- Docs (`docs/tiering.md`): the index floor is not spillable — for
  index-heavy stores the reachable saving is bounded by it; budget
  below the floor drives `effective_target` to 0. Stated *before* the
  knobs, not after.

### V6 — INFO says what a container operator needs (D4 adjacent, F16.2)

- `# Memory`: `process_rss_bytes` (Linux `/proc/self/statm`, macOS
  `task_info`, 0 elsewhere) beside `used_memory`, with a docs line:
  size containers from RSS; `used_memory` is the store, not the
  process.

### V7 — error interop is kevy's to provide (F2, orphan rule)

- `impl From<KevyError> for std::io::Error` in `kevy-client`,
  `kevy-client-async`, `kevy-embedded` — kind-mapped (timeouts →
  `TimedOut`, connection → `ConnectionRefused`, etc.) and
  **source-preserving** (`io::Error::new(kind, e)` keeps the typed
  error retrievable), which is strictly better than the 280
  `io::Error::other` conversions it replaces.
- UPGRADING: fix the kevy-client version row (2.0.0, F1); add the
  honest migration paragraph (what the change actually consists of,
  incl. the `--message-format=json` technique mailrs derived).
- `with_auto_aof_rewrite_disabled()` named builder (F4).

### V8 — the migration chapter (D5)

`docs/table-migration.md` (+ prominent link from `tables.md`), built
directly from the eight lessons, in their order of need:

1. First question: is every query dimension **single-valued on the
   row**? (The answer is in the id-derivation code, not the row.) If
   no → membership row per (owner, item); the ORDERPATH sorts that.
2. Derived rows: **every writer is load-bearing** once reads are
   served — enumerate writers before cutover; the one that forgets is
   the one written before the table existed.
3. Backfill from the **union** of every source that can name an item —
   legacy indexes disagree with each other, and VERIFY cannot see a
   row never written.
4. Shadow-read recipe: compare content **and order**; report the first
   divergence with both sort keys.
5. Deleting the old structure: enumerate **readers first**, writers
   second — a missing key reads as 0, not as an error.
6. A predicate the row lacks ⇒ another ORDERPATH, never a duplicated
   column (that rebuilds the drift you just removed).
7. Boot pattern: `table_ensure`, and what a spec diff means.
8. Lead the whole doc with the verifiability argument and the measured
   drift classes (never-written 89 %, never-removed 76 %, score-drift)
   — the engine maintaining the index is the only version of it that
   can be verified.

## Ordering and gates

`V1 → V2 → V3 → V4` are one thread (the TABLE face), `V5 → V6` the
tiering thread, `V7 → V8` the paper thread; threads are independent,
trains inside a thread are ordered. Every train lands with its gate
(facadegate / fuzz `table_spec` / oracle cases / tiergate idle line) and
the five-axis close. Ship = v4.1.0 after all eight.

## Not in scope (recorded, not deferred silently)

- F13's "row freshness signal" (rows-not-written-since-T): a real
  feature with real design questions (what clock, what prefix
  semantics); it gets its own RFC rather than a rushed corner of this
  one. The migration chapter documents the audit technique that stands
  in for it.
- F16's deeper wish — a spillable index tier — is the v5 experiment's
  T5 (index hot/cold windows), already on that roadmap.
