# R2c:滑动机制 —— 窗口怎么动,数据怎么不丢

> R2 RFC 后半之二(前半 = 窗口模型,后半之一 = R2b 冷段)。**设计文档**;
> T-manifest 的界面由本篇 §四定形。纪律照旧:4.1-V5 的收敛课
> (idempotent is not convergent)是本篇每一节的前置约束。

## 一、窗口边界 W 的维护

- `W = max_observed(窗口列) − span`。**max_observed 的来源**:窗口声明(R2a)要求
  窗口列被至少一条访问路径覆盖(ORDERPATH 含窗口列或窗口列单列索引)——树尾即 max,
  O(log) 读、无新账;若表声明 WINDOW 但无窗口列访问路径,声明期具名拒绝
  ("WINDOW needs an access path on <col>"—— Law 3 的一致语气,顺便替用户把
  跨窗查询的路都修好)。
- **单调 + 桶粒度滞回**:W 只前进不回退(旧值写入=复活,不拉回边界);
  W 按**桶**推进(粒度 = 滑动粒度,预设一天,声明可调 `WINDOW activity SPAN 90d BUCKET 1d`)
  —— 抖动天然消失,出窗单位与段单位重合(桶 = 段,R2b 3c 同构)。
- per-shard:W 是全表一致值(max 跨 shard 归并?)——**否,per-shard W**。
  行按 key 路由,窗口列与 shard 无关 ⇒ 各 shard 的 max_observed 不同。
  两案:(a) 全局 W(cross-shard 归并,一跳成本+一致性协议);(b) per-shard W
  (各自滑动,查询编译期用**全局最保守 W**= min(shard W) 判三态)。
  **倾向 (b)**:结构简单、无跨 shard 协调;代价 = 编译期三态判定要用保守边界,
  straddle 区间略宽 —— 语义仍准(查询结果不受 W 影响,只有路径分层受)。

## 二、出窗:发现、成批、构建

- **发现是免费的**:出窗候选 = 窗口列访问路径的树上 `< W` 的前缀 —— O(出窗数),
  永不扫全量。无候选时 tick 一个比较即返(收敛判据①:idle 恒零)。
- **成批 = 整桶**:W 跨过桶界 → 该桶进入"迁移中"状态;桶内行按窗口值序收集
  (天然聚簇,R2b 行段的键序免费);批大小有上界(桶),构建预算化
  (每 tick ≤N 行喂 SegBuilder,vlog 分批前例)。
- **构建执行位**:server = persist worker 线程(BGSAVE/rewrite 前例,不占 reactor);
  embedded = tick 内预算化分片构建(manual tick 语义一致;单线程锁窗已有 256KiB
  spill 上限的先例约束段构建的单步粒度)。
- **构建输入的一致性**:迁移中桶的行仍在热层、仍可写(复活语义在迁移中 = 写热层
  照常;段构建收集的是**快照视角**,COW SnapshotView 前例)。段 seal 后对账:
  构建期间被改写/删除的行(版本比对)从"待删清单"剔除 —— 它们留在热层,
  段里的旧版本被热优先语义遮蔽,compact 时清。

## 三、核心不变量与删除次序

> **任意时刻,每行至少活在一处可恢复真相里(热层+AOF,或段+manifest)。**

出窗五步,顺序即正确性:
1. 段构建(数据页写 + fsync);
2. manifest 追加(段 S 登记:表/桶/min-max/行数)+ fsync;
3. **AOF 追加内部效果帧 `SEGMENTED <table> <bucket> <seg-id>`**(见 §四);
4. 热层删除桶内行 + 对应索引条目(整段摘除,R2b 3b 的树前缀 split);
5. 段目录(内存)登记,查询归并生效。
crash 于 1-2 之间:段文件无 manifest = 启动清扫的垃圾,行仍在热层+AOF ✓;
crash 于 3-4 之间:行同时在段与热层 = 读侧热优先,重复无害,重启 replay 到
SEGMENTED 帧时补做第 4 步(幂等)✓。

## 四、AOF 缝合(= T-manifest 的界面)

- **`SEGMENTED` 是内部效果帧**(SPOP→SREM 效果帧先例):replay 遇到它 ⇒
  "该桶已入段 S":从热层删除该桶已重放的行(用段 min-max + 表前缀界定),
  并要求 manifest 中存在 S(不存在 = manifest/AOF 撕裂,具名拒绝启动,
  指向修复路径 —— 数据没丢,拒绝比静默重复好)。
- **replay 后热窗 = 真热窗**:历史行的 SET 帧在其 SEGMENTED 帧之前,重放进热层
  又被 SEGMENTED 请出 —— 中间态内存峰值 = 一个桶,可接受;rewrite 后的 AOF
  不再含已入段行的命令流(rewrite 输出 = 热层流 + 首帧 SEGMENTED 序列),
  峰值消失。
- **冷行删除需要持久墓碑**:DEL 打在段内行 ⇒ AOF 记 DEL 帧(照常)+ 段目录墓碑
  (内存 delete-bitmap);replay 时 DEL 帧对热层 no-op,但**replay 逻辑同时查
  段目录 bloom,命中则重建墓碑** —— 墓碑的持久形态就是 AOF 里的 DEL 帧本身,
  不需要新帧型。compact 物理清墓碑后,rewrite 掉这些 DEL 帧(对账:墓碑数
  归零 ⇔ 无悬空 DEL)。
- **复活不需要持久墓碑**:复活 = 写帧(SET/HSET)照常入 AOF;热优先遮蔽段内旧版;
  compact 清。
- 备份 = AOF + dump + manifest + 段集(R2b §四);`SEGMENTED` 帧使 AOF 单独
  不再完备 —— **UPGRADING/persistence.md 必须重述真相集**(文档义务,T-manifest 交付)。

## 五、判据(gate 承载)

- 收敛:无出窗时 tick 成本 = 1 比较(计数器断言);滑动稳态成本 ∝ 出窗行速率,
  与热窗容量无关(两个规模对照)。
- crash 矩阵(T-manifest):五步序的每个间隙 kill ×{构建中/manifest 中/SEGMENTED
  后/删除中},重启后 digest 与不 crash 基准逐字节等(crashgate 体裁)。
- 复活/删除 e2e:出窗 → 复活写 → 重启 → 行在热层版本正确;出窗 → DEL → 重启 →
  行不可见(墓碑经 DEL 帧重建)。
- KV/pubsub 赢线保持;无 WINDOW 表 byte-identical(A5)。

## 六、train 修订(R2b §六的顺序更新)

1. **T-manifest**(本篇 §三/§四为规格):manifest 石头面(追加/紧缩/清扫)+
   `SEGMENTED` 帧 + replay 缝合 + crash 矩阵。**T-scalar/T-row 的共同前置。**
2. T-scalar(冷段查询归并,跨窗 COUNT 走 kevy-seg count_range —— 热段 claused
   COUNT 已先行落地)。
3. T-row(行段 + 段目录/bloom + 双源 SCAN + 复活/墓碑)。
4. T-text(桶段主战场)。

## 七、发散区(本轮)

1. **SEGMENTED 帧顺便是复制协议的窗口化**:replica 收到它做同样的请出 ——
   复制自动获得窗口语义,段文件经 full-sync 传输(R2b 发散 2 的落点提前出现)。
2. **迁移中桶的"半透明"观测**:INFO 暴露 `window_migrating_bucket` 与进度 ——
   SME 的"现在在干什么"可见性,S3 的小奉献。
3. **桶粒度自适应**:写入速率高的表自动缩桶(段大小均匀)——记为 v-next,
   首版固定粒度(可声明)。
