# RFC · R4c — 迁移那天(design round,零实现)

> **状态**:设计轮,**未拍板**。本文不含实现代码,也不改任何现有行为。
> **触发**:`.claude/plans/2026-08-05-v5-status.md` §二.2 —— 三件阻塞里
> 现在唯一没动的一件。R4a 自己写着 **"专业性 = 迁移那天的体验"**,而
> 第一公里是空的。

---

## 0. 一句话

**`docs/table-migration.md` 的八课是一份写得很好的需求文档,但它今天只
存在于读者的脑子里。** 本轮问的是:这八条里,**哪几条机器能替人做**、
各自的表面长什么样、哪几条**注定是清单不是工具**(说清楚比硬造工具重要)。

## 1. 今天已经有什么(先别把已有的当缺口)

| 已有 | 是什么 |
|---|---|
| `kevy-cli migrate export/import/copy-prefix` | **kevy ↔ kevy 搬数据**:遍历键空间产 rebuild 帧、断点续传(`.progress` fsync 到批)、re-prefix 拷贝 |
| `kevy-sql` | **声明期** schema 编译:SQL DDL → `TABLE.DECLARE`,不认识的东西按名字拒绝并报行列 |
| `TABLE.ENSURE` / `TABLE.REPLACE` | 第 7 课的引擎面已经齐了 |
| `TABLE.VERIFY` / `IDX.VERIFY` | 第 8 课的**数据**齐了(计数器每次调用现算、双向) |
| `IDX.ADVISE` / `AUTODECLARE` | 第 6 课的引擎面(缺路径 → 补路径,而不是复制列) |

**所以缺的不是引擎能力,是"那一天"的工序**:搬数据的那半边有了,
**定 schema、比对、切换、验收**那半边没有。

## 2. 八课逐条:机器能做到哪

| # | 课 | 机器能做吗 | 形态 |
|---|---|---|---|
| 1 | 每个查询维度在行上是不是单值 | **能,而且是事后可判定的** — 给一个候选列,扫前缀采样,报"这个维度在 N% 的行上不单值"。真实案例(thread per mailbox)的答案在 **id 构造代码**里,但**症状在数据里**:同一 item 出现在多个 owner 下 | `migrate lint`(声明前跑) |
| 2 | 每个写者在读切过去之后都是承重的 | **不能从存储判定**(这是代码审计),但**后果能测**:声明后跑影子期,盯 `missing` | 归到 #4 的影子工具 + `doctor` 的 watch 模式 |
| 3 | 回填要取"所有能点名这个 item 的来源"的**并集** | **能** — 多来源并集是纯机械活:旧索引键集 ∪ 主键空间扫描 ∪ 归档 | `migrate backfill --from …`(可多次给) |
| 4 | 切换前影子读,**内容和顺序都要比** | **能,而且这是最值钱的一件** — 跑旧路径与新路径,比集合**也比顺序**,首次分歧带**两边排序键**打一行日志 | `migrate shadow` |
| 5 | 拆旧结构:**先读者后写者** | **不能判定** — 引擎不跟踪任意键的读者。硬造一个"没人读了"的探针会给出假的安全感 | **留在清单里,并写清为什么没有工具** |
| 6 | 缺谓词 ⇒ 再加一条 ORDERPATH,**不是复制一列** | **能提示** — 同表两列在 ≥X% 行上取值相同 = 疑似复制;更正的入口本来就是 `IDX.ADVISE` | `migrate lint` 的第二条规则 |
| 7 | 用 `ensure` 开机 | **引擎面已齐**;能加的是**代码里的 spec 与库里的 spec 对不对得上**(拿 schema 文件跟 `TABLE.LIST` 比) | `migrate plan --check` |
| 8 | 把 `VERIFY` 变成运维日常,不是迁移的一步 | **能** — 计数器已经在了,缺的是**能进 cron 的外壳**:退出码、阈值、哪几个必须恒为零 | `doctor` |

**两条注定不是工具(第 2、第 5)。** 把它们写成"清单项 + 为什么机器做不了",
比造一个假探针诚实,也更有用 —— 假探针在第 5 课上尤其危险:那一课的
失败模式本来就是**静默正确地读到空**。

## 3. 提议的交付物(按价值排序,不按容易排序)

### T1 · `migrate shadow` —— 影子比对(第 4 课,也含第 2 课的后果面)

给一对"旧问法 / 新问法",持续采样比对:

* 比 **集合** 也比 **顺序**;
* 首次分歧输出**双方的排序键**(这一行日志直接点名漂的那个写者);
* 报 `missing`(新路径没有的)与 `extra`(新路径多出来的)两侧;
* 结束时给一句可粘贴的结论:样本数、分歧数、首次分歧的键。

**为什么排第一**:它是唯一能把"我不敢切"变成"我可以切"的东西,
而且它同时兜住第 2 课(忘掉的写者会以 `missing` 现形)。

### T2 · `migrate backfill --from <源> …` —— 并集回填(第 3 课)

来源可给多个:`--from-index <name>` / `--from-prefix <p>` / `--from-file <keys>`。
先求并集再写行,**并且报告每个来源各自贡献了多少独有键** —— 那个数字
本身就是 89%/76% 漂移的现场证据,值得让人看见。

### T3 · `migrate lint` —— 声明前的两条规则(第 1、6 课)

* **单值性**:候选列在采样行上是否单值;不单值时直接给出
  membership-row 的形状建议(`member:{owner}:{item}`)。
* **疑似复制列**:同表两列取值高度重合 → 指向 `IDX.ADVISE`。

跑在 `TABLE.DECLARE` **之前**,因为第 1 课的原话是"先定这个,免得整张表
重新声明"。

### T4 · `doctor` —— 把 VERIFY 变成运维回路(第 8 课)

对所有表跑 `TABLE.VERIFY`,把计数器映射成退出码:
`drift`/`missing` 非零 = 失败;`duplicates` 非零 = 警告(分页需要有界
tie-break);`absent`/`excluded`/`coerce_failures` 只报告。适合 cron。

### T5 · `migrate plan` —— 第一公里(pg_dump → kevy)

吃一份 schema(`kevy-sql` 已经能编 DDL)**加一份查询清单**,产出:
* 建议的 `TABLE.DECLARE`(列、索引、ORDERPATH);
* **查询卡片**:每条查询 → 由哪条声明路径服务;**服务不了的按名字列出来**,
  并给出"要么加这条 ORDERPATH,要么这条查询在 kevy 上不成立"的选择。

**这才是"迁移那天的体验"的正脸**:一个人拿着自己的 schema 和自己的
查询来,应该在十分钟内知道**哪些能过、哪些不能、不能的怎么办** ——
而不是读完八课自己推。

## 4. 放哪(石头/钢筋/水泥)

* T1/T2/T3/T5 的**逻辑**:钢筋 —— 认识 kevy 的领域模型(表、路径、行),
  不绑任何具体业务流。建议新 crate `kevy-migrate`,`kevy-cli` 只做外壳。
* T4 `doctor`:同上,但更薄,可以直接住在 `kevy-cli`。
* **零依赖铁律照旧**:全部 std + 自家 crate。

## 5. 需要拍板的(属主)

1. **范围**:五个交付物全做,还是先做 T1+T4(能切换、能验收)、把
   T5(第一公里)留到下一轮?我的建议是 **T1 → T4 → T5 → T2 → T3**,
   因为前两个决定"敢不敢切",T5 决定"愿不愿来"。
2. **T5 的输入格式**:查询清单是自定义的一行一条,还是吃 SQL 文件让
   `kevy-sql` 解析?后者更像"拿你现在的东西来",但会把 `kevy-sql` 的
   拒绝面推到查询侧(今天它只管 DDL)。
3. **新 crate `kevy-migrate` 是否开**,还是全部塞进 `kevy-cli`(现在
   `migrate.rs` 已 310 行,再加四个子命令必然要拆)。
4. **第 2、5 课明确不做工具** —— 需要属主确认这是"决定"而不是"遗漏",
   我会把理由写进 `docs/table-migration.md` 对应两节。
