# RFC — v5.3: the systematic test suite (three tiers), the architecture toolchain, and the release flow

Owner directive (2026-08-17): make kevy's testing systematic as the core
of 5.3. Three tiers — `precommit < prerelease < full` in cost, strictly.
`full` hunts problems and leaves no standard unexamined; `prerelease`
pins regressions, the current version's goals, and the iron rules;
`precommit` pins the current version's goals plus the regressions and
standards that can be pinned fast. Content must cover: performance,
disk, memory, docs, standard Redis/RDS compatibility, dialects,
performance versus peers, kevy's own features, and the classic cases.
Also: a toolchain for clean architecture, cleanup of build/test
artifacts, and the release skill flow built around all of it.

## 1. What exists, and what the problem actually is

The material mostly exists — 92 scripts in `bench/`, 16 checks in
`tools/`, 21 CI jobs. What does not exist is the **system**:

- Nothing says which checks constitute a tier, so "run the gates" is a
  memory exercise, and memory is what failed every time this repository
  shipped a lie (the six version layers, the 218 KB wasm, the missing
  changelog page).
- Nothing accounts for coverage. A check can vanish (the changelog page
  did; `check_cjk_punct` went blind to `.tsx` for a whole redesign) and
  no ledger says an area went dark.
- Nothing enforces cost. `pushgate` grew until it stopped being a
  pre-push habit; the five owner-claim gates live only in the release
  skill's prose.
- ~40 of the 92 scripts are exploration probes (`v125-*`, `axis_*`),
  indistinguishable at a glance from load-bearing gates.

So 5.3 is not "write more tests". It is: **a manifest that is the single
source of truth for what is checked, a runner that enforces tier
budgets and coverage floors, the few genuinely missing checks, and the
release flow rewritten on top.**

## 2. The tier contract

| tier | purpose | budget (wall) | verdict |
|---|---|---|---|
| `precommit` | pin the current version's goals + the regressions and standards that pin fast | **≤ 5 min** | every check hard |
| `prerelease` | pin regressions, release claims, iron rules | **≤ 90 min** | every check hard; box checks report NOT-RUN loudly when off-box |
| `full` | find problems; no area dark | unbounded (per-check timeouts) | hard checks fail the run; advisory checks report |

Invariants, enforced by `tools/suite.py --audit` (not by convention):

1. **Subset**: checks(precommit) ⊆ checks(prerelease) ⊆ checks(full).
2. **Budget order**: budget(precommit) < budget(prerelease); full is
   unbounded but every check carries its own timeout.
3. **No dark areas in full**: every area below has ≥ 1 check in `full`.
4. **Floors**: the manifest itself has a count floor; a check whose
   command file does not exist fails the audit — a deleted gate cannot
   silently leave the suite.
5. **Skip is not pass**: a check whose infrastructure is absent (box,
   device, Chromium, docker) reports NOT-RUN by name; the tier verdict
   lists them. `full` with NOT-RUN rows is "full minus these", said out
   loud, never a bare green.

Exploration probes (`v125-*`, `axis_*`, `loopback_*`, one-off decomps)
are **deliberately outside the manifest**: they are instruments for
finding, not standards for holding. The RFC records this so their
absence from the suite reads as a decision, not an omission.

## 4. What is genuinely new

1. **`tools/suite.py` + `suite/manifest.toml`** — the runner and the
   single source of truth. `--audit` (invariants, in CI), `--list`,
   `precommit|prerelease|full` to run. Durations recorded per check so
   budget claims are measured, not asserted.
2. **`tools/check_architecture.py` + `suite/architecture.toml`** — the
   steel/cement/stone model made mechanical: every workspace crate
   classified (unclassified = fail), stone may depend only on stone,
   steel on steel+stone, cement on anything; support (dev-only) crates
   exempt but named. Runs from `cargo metadata`, no network.
3. **`bench/dialectgate.sh`** — pins what 5.2 changed and what upgrades
   keep changing: per-dialect table surface (5.1 has `setn`+global
   `unpack`, not `table.unpack`/`create`; 5.4 has `table.unpack`),
   operand-first error wording on ≤5.2, type-first on ≥5.3, the
   `string.rep` DoS staying fixed (time-bounded call), unknown dialect
   refused. Runs against a real server binary.
4. **`tools/clean.py`** — build/test artifact reclamation with a
   report: cargo profiles, runtime residue (`aof-*`, `dump-*`, `tier/`,
   `feed-*`, `shards.meta` — the things rootgate detects, reclaimed),
   site build products (`web/dist`, `web/.ssr`), scratch stores under
   `$TMPDIR`. Default is a sized report; flags delete. Never touches
   tracked files.
5. **Release skill flow** — rewritten around tiers: `precommit` before
   every push (replaces the ad-hoc pushgate habit), `prerelease` green
   before any tag (subsumes the five owner-claim gates by name),
   `full` on a cadence and before majors. The skill keeps the tag
   trigger with the owner.

## 5. Tier membership (initial; the manifest is authoritative)

- **precommit** (~3–4 min warm): hygiene ×4, release-pins ×3, arch ×1,
  doc-fast ×7 (links, cjk, i18n, toml, md-port, wasm-size,
  readme-bench --check), dialectgate (debug server), content-export
  --check. No perf: a sub-noise perf check trains people to ignore red.
- **prerelease** (≤ 90 min): precommit + fmt/clippy -D warnings +
  workspace tests + site build/check/verify + site commands/parity +
  wasm-published (advisory between releases) + crashgate + perfgate +
  tailgate + repligate + availgate (box) + upgrade-interop + compat3 +
  cookbook_smoke + vendorgate + ffigate-contract + propgate +
  upgradegate.
- **full**: prerelease + perfgate-median + arena + kevy_ab + mem ×5 +
  disk remainder (chaosfsck, restore-drill) + feature gates ×11 +
  cases (drill_mailrs, migrationgate, onrampgate, scalesoak) + doors
  (clientgate, consumergate, jnigate, mcpgate, mobilegate-all) +
  pgcompare + covgate + capacity-envelope. Fuzz remains a CI surface
  (nightly toolchain); the manifest lists it as `requires = ["ci"]` so
  the audit knows the area is covered and where.

## 6. Resolution log

- (2026-08-17) Tiers keyed by **budget and purpose**, not by directory:
  moving a check between tiers is a one-line manifest edit, auditable.
- (2026-08-17) `pushgate` stays as a thin alias for `suite precommit`
  during the transition, then retires.
- (2026-08-17) Probes stay in `bench/` unmanifested; deleting history
  is not cleanup.
