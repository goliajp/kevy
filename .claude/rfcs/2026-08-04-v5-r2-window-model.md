# R2a+R2d:窗口模型与语义面 —— 设计轮(现状对照 + 拍板题)

> 总案 §R2 的第一设计轮("纯设计,先把'窗口是什么'钉死")。
> 实施在总案写就后已跑在前面(T 系列 + R4b),所以本轮的正确形态
> 不是白板设计,而是:**已实现的窗口模型对照总案判据逐条陈述,
> 缺口列成拍板题**。拍板权归属主;本文只陈述与建议。

## 〇、已实现面盘点(T 系列 + R4b 之后的既成事实)

1. **窗口定义 = 声明窗**:`TABLE … WINDOW <col> SPAN <n> BUCKET <n>`
   —— 总案 R2a 候选 (ii) 时间窗 / (iii) 键序窗的统一声明形
   (引擎只按 i64 序,不解释单位;时间列与单调业务键同一机制)。
2. **索引段窗口化(R2b 的第一形态)**:出窗条目滑入紧凑只读冷段
   (mmap,text/scalar/composite 三形全覆盖),热窗段 = 今天的全部
   结构;跨窗查询 = 热段 + 冷段归并(引擎内自动)。
3. **滑动机制(R2c 的第一形态)**:tick 驱动、bucket 对齐、
   幂等收敛(idle 态近零 —— idle_ticks 纪律);崩溃矩阵
   (crashgate window cells)覆盖 SIGKILL × 滑动中段。
4. **语义面现状**:KV 面完全透明(C4 底线,已由 window_rows
   KV-transparency gate 钉住);TABLE 面 = 声明窗口列,查询语义
   不变(跨窗自动归并,无须显式说)。
5. **窗口回收环(R4b-c)**:引擎观察查询触及深度(margin),
   `IDX.ADVISE` 给出 SPAN 收窄建议 —— R2×R4 合成点已通。

## 一、对照 R2a 判据:窗口边界对查询期可判定吗?

**判据原文**:一个查询在编译期就知道它命中热窗、跨窗、还是纯冷
("没有缓存未命中概念"的前提)。

**现状**:可判定性存在但只在执行期 shard 内(`WindowRt::boundary()`
对查询 bound 的比较);**声明期/EXPLAIN 面没有窗口性**:
`IDX.EXPLAIN` 不报"这个查询是热窗内/跨窗/纯冷",跨窗归并的冷读
不可见(执行了多少段归并、touching 几个冷段,查询者无从知道)。

**缺口 → 拍板题 A**:是否给 `IDX.EXPLAIN` 加窗口性输出
(hot / straddle / cold + 触及冷段数估计)?
成本小(boundary 与 bound 的比较即答案),它把"可判定"从执行期
提升到声明期,判据即闭。**建议:做**(纯加法,一小轮)。

## 二、对照 R2d 假设:透明默认 + 声明可选

**假设原文**:透明为默认 + 声明可选是对的。

**现状恰好是这个混合**:KV 面与未声明窗口的 TABLE = 完全透明;
声明了 WINDOW 的表 = 可预测边界(bucket 对齐、SPAN 明示)+
查询语义仍然不变。假设的两半都已成立,**但"跨窗查询要显式说"
的候选语义没有做**(现在跨窗自动归并,静默)。

**拍板题 B**:跨窗要不要显式?三个候选:
- B1 维持现状:跨窗自动归并,静默(零门槛,但慢查询不自知)。
- B2 硬显式:跨窗查询必须带子句(如 `COLD`),否则拒绝并 advise
  —— R4b 的拒绝语义可直接复用("拒绝即信号");
  可预测性最强,S2(专业性)最像 RDS 的显式索引提示。
- B3 软显式:默认归并,但 reply/EXPLAIN 标注 straddle(观察面
  免费拿到,不改变语义)。
**建议:B3 先行**(与拍板题 A 同一轮实现),B2 作为表级旗标
(`WINDOW … STRICT`)留给需要硬边界的表 —— 与 AUTODECLARE 同款
"默认保守、显式授权"哲学。

## 三、R2a (i) 访问窗兜底:没有天然窗口列的表怎么办

**总案假设**:(ii)/(iii) + (i) 兜底的混合是对的。现状**没有 (i)**:
表若无时间/单调列,窗口机制整体不可用,容量回到"全热"。

**拍板题 C**:访问窗((i) LRU 型)要不要做、以什么形态?
观察:R4b 的观察面给了第三条路 —— **不做真 LRU,而是观察查询
bound 分布 → advise 一个 (ii) 型窗口声明**("查询只打 id >
10^7 的行;WINDOW id SPAN … 会把 92% 的行移出热区")。
它保持窗口的可预测边界(Law 3),避免 (i) 的统计边界(查询期
不可判定,正是判据反对的)。真 LRU 兜底降级为"不建议做"。
**建议:窗口 advise(auto-window 观察)进 R4b 的 slice 谱系;
真访问窗从 scope 里划走,记 scope-decision。**

## 四、R2b/R2c 判据的欠账(陈述性,非新机制)

- R2b 判据"冷段内存成本公式化":冷段 mmap 后驻留 = 页缓存管辖,
  但**每段的元数据常驻项没有公式陈述**(段表条目、census、
  manifest)。欠一份 STONE-BENCH 式陈述文档,不欠机制。
- R2c 判据"稳态成本 ∝ 进出窗速率":idle 态近零已有纪律,
  但**没有实测陈述**(固定负载下 tick 成本 vs 进出速率的曲线)。
  欠一次 perfgate 型实验,不欠机制。

**拍板题 D**:这两份陈述文档/实验排进 R2 收口(建议:是,
它们是 R2 总判据 —— "每一项的 scale 方式可陈述" —— 的直接材料)。

## 五、建议的切片(若拍板通过)

1. R2-s1:EXPLAIN 窗口性(拍板题 A)+ straddle 标注(B3)——
   一轮,纯加法。
2. R2-s2:`WINDOW … STRICT` 表旗标(B2 的保守形)—— 一小轮。
3. R2-s3:窗口 advise(拍板题 C 的观察形)—— R4b 谱系,
   bound 分布观察已有一半(min_margin 即近端证据)。
4. R2-s4:冷段元数据公式陈述 + 滑动稳态实验(拍板题 D)。
