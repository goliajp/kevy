# T-text:文本桶段 —— 倒排的窗外部分下盘,分数不变

> R2b 的实施 RFC(text 半),423MB 主战场。范围:窗口表的 TEXT 索引,
> 出窗行的倒排条目冻入桶级冷段;MATCH 归并热+冷。

## 〇、上位拍板(两条,都有先例)

1. **text 冷段 = derived spill,不进真相集**(T-scalar 同论证:索引重启
   全量 backfill,行真相在行段/AOF)——无 SEGMENTED 帧、无 crash 矩阵、
   重启自愈清残(manifest tag 清扫,WindowRt.cleaned 同款)。
2. **分数标度靠 CorpusStats 注入,不靠归一化**。跨 shard 全局 BM25 的
   两趟架构已存在(pass1 汇 stats、pass2 注入打分):冷段只是 pass1 的
   又一个贡献者(n_docs / total_len / per-term df),它的命中分数与热
   命中**按构造可比** —— 这是探路的最大发现,整个设计围绕它。

## 一、冷段形态(kevy-seg 载体)

- 每次滑动批(= 出窗桶)一段:`txt-<hex(index)>-<seq>.seg`。
- **record key = term**(BTreeMap 冻结天然升序,满足 SegBuilder);
  payload = frozen posting list:varint 编码
  `[n_docs][per doc: klen‖row_key, tf, dl][positions blob 若声明]`
  (docblobs 的 varint helpers 就是编码器;positions blob 按 verbatim
  拷贝 —— 已是 delta+varint)。
- **doc 身份 = row key**(尖角:热 id 段内复用,冷段绝不能存 id)。
- 段级 stats(n_docs, total_len)编进 **manifest entry meta**
  (`txtcold:<name>:<n_docs>:<total_len>`)—— pass1 读 stats 零 I/O
  (FTS 会计教训:stats 贡献永不走内存/文件遍历);per-term df =
  每查询 term 每段一次 `Seg::get` O(log),payload 头部即 df。

## 二、kevy-text 新面(纯编解码 + 冻结,无 I/O)

- `freeze_docs(&mut self, keys) -> FrozenBucket`:**read-then-withdraw**
  (withdraw 消费存储源文本,顺序不可反);FrozenBucket =
  `BTreeMap<term, Vec<(row_key, tf, dl, pos_blob)>>` + (n_docs, total_len)。
  冻结即回收:doc_bytes(全源文本)、postings 槽、positions 槽全部出热。
- `cold` 模块:`encode_posting` / `decode_posting` + `score_cold`
  (对 decode 流按注入 CorpusStats 算 BM25,accumulate 模板 —— 不做
  MaxScore 剪枝:热阈值剪冷候选会**丢文档**,探路尖角 3)。

## 三、出窗编排与陈旧治理

- 骑现有滑动批:`evict_and_slide` 的 `pending_rows` keys 同批喂 text
  (行滑 → text 冻结 → scalar 切,text 失败不阻行/索引 —— text 是
  derived,漏冻结 = 留热,语义无损,计数器暴露)。
- 冷目录:`WindowRt.cold_text: Vec<(Seg, n_docs, total_len)>`
  (kevy-window 不依赖 kevy-text —— 编解码归引擎层调 kevy-text::cold)。
- **陈旧共享 scalar 的 bloom/tombs**:滑动批 keys 已插 bloom;text 写
  路径接上 `win.on_row_write`(探路尖角 6:text arm 现在 early-return
  绕过了 hook);冷命中 decode 后 row ∈ tombs → 跳。复活/删除/重写
  零新状态。
- 滑后 `malloc_trim_now`(已有钩,text 批释放源文本 Vec 正是它的场景)。

## 四、查询归并(两 train)

- **T-text-a**:term / OR(多 term 累积)的冷归并。
  - pass1 stats seam(server `ops.rs:55` / embedded `ops_index_text.rs`):
    加冷段 (n_docs, total_len)(manifest meta,零 I/O)+ df(段 get)。
  - pass2 hits seam(`scored_hits` / `gather_hits`):每冷段解码累积
    打分 → TopK → 作为第 N+1 个 ranked 列表进现有 reduce(sort/collapse/
    offset/truncate 零改动)。
  - tier 账目:冷段在盘,**不入** reserved_bytes(尖角 7)。
- **T-text-b**:phrase 冷路径(positions blob verbatim 已在段里)+
  facet/FILTER/SORT/highlight 冷补全。期间这些 clauses 在**有冷桶的
  text 索引**上具名拒绝(COLD_CLAUSE 姿势,静默少文档不可接受);
  纯 term/OR + LIMIT 查询正常归并。highlight 冷命中:源文本已不在热
  —— 回行段读(行已下盘,row seg get)或拒;a 版先拒,b 版随行段读接。

## 五、gate

1. MATCH 语义等价 e2e:带窗 vs 对照,term/OR 各形,出窗后 + 复活/删除/
   重写 churn 后,**分数与排序逐字节等**(同 CorpusStats 同公式)。
2. 有冷桶时 phrase/FILTER/SORT/FACET/HIGHLIGHT 具名拒;对照面照常。
3. 内存:text approx_bytes 实测下降(doc_bytes + postings 出热),
   三件套体裁加 text 列。
4. 无 WINDOW / 无 TEXT 部署 byte-identical;perfgate 复跑(apply_row
   text arm 加 hook,无窗成本必须为零)。

## 六、切分

1. **T-text-a1(石头层)**:kevy-text `freeze_docs` + cold codec +
   单测(冻结回收账目恒等、codec 往返、score_cold 与热打分对齐 pin)。
2. **T-text-a2(接线)**:出窗编排 + 双面 pass1/pass2 seam + 拒绝面 +
   e2e + perfgate。
3. T-text-b:phrase/facets/highlight 冷路径。

## 六b、b-train addendum(2026-08-02,a2 收口后拍)

1. **冷 doc 的 stored values 冻入段内 doc record**(fwd 记录扩展
   `[dl][terms][values]`),不走回行读:FACET 数的是**全匹配集**,回行
   读是 O(match set) 次行 I/O;冻入段后一次 fence descent 即取,段保持
   自含。HIGHLIGHT 仍按 §四 回行读(源文本冻入段 = doc_bytes 不出热,
   内存收益归零)——页面有界,每命中一读。
2. **选择序语义**:SORT 下热面按 okey 序选页(`sorted_order` 公开正是
   为跨源归并),冷候选必须按**同一页序**选择与归并,不能按分数;
   DISTINCT 在 shard 级 merge 后重 collapse(分布式 top-k 论证:真页
   成员必在其源的 collapse 页内)。FACET:冷桶按 identity 与热桶求和,
   label 热先冷后,重排 (count desc, label asc) —— 与 count_facet 同序。
3. **a2 遗留修正**:冷归并曾直接 `tokenize` 不 dedup 不剥引号;b 起
   pass-2 冷面走公开化的 `parse_clauses`(bare sort+dedup,phrase 独立
   贡献)—— 与热 `accumulate_clauses` 严格同构。
4. **b 后仍拒**:prefix `*`(词典已失,段可 range-scan 但 RFC 不含)、
   TYPO(词典编辑距离展开)、IN scope(per-field 通道冻结时坍缩)。
   拒绝文案同步缩窄。

## 七、发散区

1. **冷段 df 缓存**:热 query 重复 term 的段 get 可挂 per-段 LRU ——
   等实测,不预做。
2. **段间 term 合并(compaction)**:多桶段同 term 命中多次 get;
   桶段合并成月段 —— v-next,与行段 compact 同机制。
3. **冻结桶的 dl 分布直方图**进 manifest meta —— 未来 MaxScore 冷剪枝
   的安全前提(有全局界才能剪),记档不做。
