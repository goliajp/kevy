# v1.27 — Lua bridge via luna

**Status:** Draft (blocked on luna v1 publish to crates.io). 2026-06-23.

## Goal

Add Redis-compatible Lua scripting to kevy via the in-house pure-Rust
luna runtime (`~/workspace/labs/lab31-luna`). Closes the v2-8 placeholder
in the kevy v2 plan; this is the first script-host feature on kevy.

## Design lock-in

User decision 2026-06-23: **"default 5.1 不破生态,但我们支持新的插件用 5.1-5.5
任何一个来写"** — shape II from the option matrix.

### Ecosystem-compat shape (locked)

- **Default = Lua 5.1.** A script with no shebang executes under
  `LuaVersion::Lua51`. Every Redis-ecosystem script (BullMQ, Redlock,
  rate limiters, anything copied from Redis docs) runs unmodified.
- **Per-script opt-in to 5.2 / 5.3 / 5.4 / 5.5** via the first-line
  shebang `#!lua version=5.3` — extending Redis 7.0's existing
  `#!lua name=...` Functions syntax with a new `version=` key
  (orthogonal, no new reserved word).
- **SHA1 cache key = raw script bytes** — version sits inside the
  shebang line, so EVALSHA cache lookups are version-aware for free,
  no extra RESP field.
- **`[lua] allow_dialects = ["5.1"]` config** lets operators lock the
  server to pure Redis-compat mode (degrades to "5.1 only" form).
- **Anti-patterns rejected** (recorded for posterity):
  - Pure 5.1 (wastes luna's multi-dialect capability — = valkey).
  - 5.5 default + `LANG 5.1` flag (breaks Redis drop-in — existing
    ecosystem scripts would need per-EVAL flag).

### Shebang syntax

Borrowing Redis 7.0 Functions' `#!lua name=...` pattern:

```lua
#!lua version=5.3 flags=no-writes
-- script body — uses Lua 5.3 integer/float split
local i = 10 // 3   -- integer divide, 5.3+
```

Recognized keys (order-insensitive, whitespace-delimited):
- `version=5.1` | `5.2` | `5.3` | `5.4` | `5.5` — picks the luna VM
  dialect. Unknown → reject with `-ERR unknown lua version`.
- `flags=no-writes` — Redis 7.0 compat marker (currently noop in
  kevy, parsed and ignored; cluster routing won't gate on it in v1.27).
- `name=...` — Redis 7.0 Functions key, ignored for plain EVAL (v1.27
  doesn't ship FUNCTION yet — v1.28+ candidate).

Missing shebang → `version=5.1, flags=` defaults.

## Crate layout

New `crates/kevy-lua` — "steel" in the stone-cement-stone model
(business-domain-aware, not bound to a specific business flow). Public
surface ≤ 7-10 functions per the kevy CLAUDE.md house rule:

```
kevy_lua::Bridge        // per-shard bridge holder
  ::new(host)           // create from a HostBridge impl (kevy-rt)
  ::eval(script, keys, args) -> Reply
  ::evalsha(sha1, keys, args) -> Reply
  ::script_load(script) -> [u8; 20]
  ::script_exists(&[sha1]) -> Vec<bool>
  ::script_flush(mode)
  ::set_allowed_dialects(&[LuaVersion])
```

Dependencies:
- **`luna-core = "1.1"`** from crates.io (NOT `luna` — that name was
  taken; NOT `luna-jit` — it pulls 74 transitive cranelift deps and
  would break the 0-dep rule). `luna-core` is the pure-interpreter
  workspace member of the luna 1.1 split. `cargo tree -p kevy-lua`
  must continue showing 1 third-party dep (just `luna-core` itself).
- `kevy-bytes` for `SmallBytes` zero-copy marshaling.
- `kevy-resp` for the reply encoder.
- 0-crates.io-dep workspace rule preserved (luna-core is itself 0-dep,
  CI-gated on the luna side via `cargo-deny`).

## RESP commands

| Command | Behavior |
|---|---|
| `EVAL script numkeys key... arg...` | Compile-or-cache by SHA1, marshal KEYS/ARGV, run on the script's dialect VM, encode reply. |
| `EVALSHA sha1 numkeys key... arg...` | Look up the cached chunk; `-NOSCRIPT` if missing. |
| `EVAL_RO` / `EVALSHA_RO` | Read-only variants (Redis 7.0+). Reject any `redis.call` that would mutate. |
| `SCRIPT LOAD script` | Cache without running, return SHA1 hex. |
| `SCRIPT EXISTS sha1...` | Multi-bool reply. |
| `SCRIPT FLUSH [ASYNC\|SYNC]` | Drop the per-shard cache. ASYNC = scheduled; SYNC = immediate (v1.27 implements both as SYNC; tag the difference for future). |

Not in v1.27:
- `FUNCTION LOAD` / `FCALL` (Redis 7.0 Functions — separate command
  surface, v1.28+ candidate).
- `cjson` / `cmsgpack` (C-interface libs in real Redis — violate
  0-dep; revisit when pure-Rust replacements exist).

## Lua-side host API

| Symbol | Behavior |
|---|---|
| `redis.call(cmd, ...)` | Dispatch through the normal kevy command path; on error, raise a Lua error. |
| `redis.pcall(cmd, ...)` | Same, but error becomes a table `{err = "..."}`. |
| `KEYS` / `ARGV` | Global 1-indexed string arrays from the RESP argv. |
| `redis.status_reply(s)` / `redis.error_reply(msg)` | Build the simple-string / error replies. |
| `redis.sha1hex(s)` | Hex SHA1 of a string. |
| `redis.log(level, msg)` | Levels DEBUG / VERBOSE / NOTICE / WARNING. |
| `redis.replicate_commands()` | Noop (Redis 7+ already always-on). |
| `redis.breakpoint()` / `redis.debug()` | Stub-return false (no LDB in v1.27). |

## Execution model

- **VM per-shard, per-dialect, lazily spawned.** First EVAL hitting
  `version=5.3` on shard N constructs `Vm::new(LuaVersion::Lua53)` on
  that shard; the VM is reused for every subsequent 5.3 EVAL on shard
  N. Idle RSS impact: ~few MB × 5 dialects × `--threads`. Lazy spawn
  keeps a server that only runs 5.1 scripts at one VM per shard.
- **Atomicity:** entering EVAL on shard N pauses other command
  dispatch on that shard until the script returns. Matches Redis
  semantics. The per-shard runtime already serializes dispatch, so
  this is "don't yield in the middle" — no new lock primitive.
- **Fuel / time limit:** luna's per-call instruction budget gates max
  runtime. Default `lua-time-limit = 5000` (ms), Redis-compat default.
  Configurable via `[lua] time_limit_ms = N`.
- **KEYS slotting:** in cluster mode all KEYS must hash to the same
  CRC16 slot owned by the current shard; cross-shard KEYS → `-CROSSSLOT`.
  Single-shard mode (default) doesn't gate.
- **SHA1 cache:** per-shard `HashMap<[u8; 20], CompiledChunk>`. Lifetime
  = shard lifetime; cleared by `SCRIPT FLUSH`. Cache is
  per-shard-private (shared cache would need cross-shard sync we
  don't want).
- **Read-only mode** (`EVAL_RO` / `EVALSHA_RO`): `redis.call` checks
  the dispatched command's write-flag table; mutations raise
  `-READONLY can't write against a read-only script`.

## Marshaling — RESP ↔ Lua

| RESP | Lua (5.1) | Lua (5.3+) |
|---|---|---|
| Simple string `+OK` | `{ok="OK"}` table | same |
| Bulk string `$N\r\n...` | string | string |
| Integer `:N` | number | integer |
| Error `-X` | error | error |
| Nil bulk `$-1` | false | false |
| Array `*N` | 1-indexed table | 1-indexed table |

Returning from Lua:
| Lua | RESP |
|---|---|
| nil | `$-1\r\n` (nil bulk) |
| number (5.1) / float | bulk string (Redis quirk — integer reply requires `tostring` or table) |
| integer (5.3+) | `:N\r\n` (integer reply) |
| string | bulk string |
| `{ok="..."}` table | simple string |
| `{err="..."}` table | error |
| array table | array, stops at first nil (Redis semantics) |
| boolean | true → `:1`, false → `$-1` |

The 5.3+ integer distinction is one of the user-visible upsides of
opting into a newer dialect.

| **P6** | EVAL_RO / EVALSHA_RO read-only enforcement |
| **P7** | Atomicity + fuel limit integration with kevy-rt shard dispatch; `vm.set_instr_budget(Some(lua_time_limit_to_instrs(ms)))` from `[lua] time_limit_ms` config |
| **P8** | BullMQ + Redlock + rate-limiter smoke (real-world ecosystem scripts run unchanged on default 5.1). Reuse `/tmp/lua-ecosystem-survey/` corpus from the v1.1 evaluation work |
| **P9** | Bench (luna v1.1 already adds `redis_lua_shape` cell to its own bench; we add kevy-side end-to-end EVAL bench) + docs (docs/lua.md en/ja/zh, kevy-lua README, README.md headline update) |

**Optional consideration for P1+:** luna v1.1 added a `Lua` newtype
facade (B12) — `mlua`-shape front door with owned `LuaFunction` /
`LuaTable` / `LuaRoot` handles. If we use `luna_core::Lua::new()`
instead of `Vm` directly, the kevy-lua bridge body shrinks further.
Open question — `Lua` facade vs `Vm` low-level — defer decision to P1
when we see which feels better in code.
