# T-row:行段 —— 值下盘,键仍热,真相换家

> R2b/R2c 的实施 RFC(行段半)。**对 R2b 的一处具名偏离**见 §〇;
> 其余(段=持久真相、五步序、SEGMENTED 帧)照 R2b/R2c 执行。

## 〇、上位拍板:行出窗 = 温度相变到 stub,"零残留"降为 v-next

R2b 原文设想行 key 从热层整体消失(零残留,bloom+目录补语义)。探路实证
推翻了这个起点的性价比:value-tier 已经用"24B ColdRef stub 留在 map"
买下了 **EXISTS/TYPE/TTL/SCAN/DBSIZE/RANDOMKEY/DEL/RENAME/reaper/snapshot
全部免费正确**(tier.rs:5-7 的构造性论证,~196 个 Value match 站点零改动);
key 消失则每一处都是要单独补的洞,且 HSET 在缺 key 时走 create 分支会
**静默丢掉冷行的未写字段**(hash.rs:382→426 实测路径)。

**拍板:行出窗 = `Entry.value` 相变为指向段的 stub(键/Entry/TTL 仍热),
不删 key。** v5 的真收益 stub 版全部拿到:

- **AOF rewrite / snapshot 不再背冷行数据**(只背轻 stub)——rewrite 快、
  snapshot 小、重启加载快;
- **备份 = 拷段 + manifest 增量**(段不可变);
- 读写语义透明由 tier 前例逐条继承。

残余成本 = 每冷行 ~100B 热内存(key+Entry+stub)。SME 百万行 = ~100MB 级,
可接受;真要抠时,"stub 也下盘"(bloom+目录版)记 v-next,且到时只是
在**已正确**的系统上做纯内存优化,不再背语义风险。

## 一、与现有 value-tier 的关系:第二个 backing,不是第二套机制

现有 tier:内存压力驱动、vlog 存储(per-boot disposable)、snapshot 时
materialize_cold 读回。行段:**窗口声明驱动、段存储(持久真相)、
snapshot 存 stub 不读回**。同一 `Value::Cold` 通道分流两个 backing:

- `ColdRef` 现 24B(offset/file_id/len/weight/tag/touched)。行段 stub 复用
  该结构,`file_id` 高位作 backing 判别(vlog | seg),seg 侧 offset/len
  语义换为段序号(目录内 index);tag/touched/weight 语义不变。
  196 个 match 站点因此**零改动**(它们只认 `Value::Cold`)。
- `tier_serve`/`tier_resolve`/`tier_peek_value`/`peek_hash_fields` 的
  Cold 分支按 backing 分流:vlog pread ↔ `Seg::get(key)`(O(log) fence)。
  promote 语义同款(materialize-then-write,HSET 合并语义自动保住)。
- revive 后段内旧条目成垃圾:**不需要墓碑** —— 读永远走热层 stub/热值,
  stub 被替换后段条目不可达。per-seg dead 计数(目录内存态)喂 compact
  (compact 本身 v-next)。

## 二、出窗:谁、何时、怎么切

- **资格**:窗口表(WINDOW 声明)前缀下、窗口列值 < W 的 hash 行。
  发现走窗口列索引的 `< W` 前缀(T-scalar 的 WindowRt 已维护 W;行滑与
  索引滑同 tick 同批 —— WindowRt 扩出 row half,批 = 同一批 row key)。
- **TTL 行不出窗**(key TTL 或 field TTL 皆拒,静默留热):TTL 表示短命,
  下盘只会马上背回 reaper 语义;段 payload 因此不需要 TTL 编码。
  文档言明;计数器暴露被跳过的行数。
- **编码**:段 payload = `[ver u8]` + tier_codec 的 hash body(字段名/值,
  编码归一化与 tier 同策略);段 key = **row key 本身**(收集后按 key 排序
  再喂 SegBuilder;apply_segmented 的"段 key = 行 key"约定继续成立)。
- **五步序**(R2c §三,首个真产者):段 build+fsync → manifest add(fsync,
  meta = `rowcold:<table>`)→ **AOF 记 SEGMENTED 帧** → 热层相变
  (`demote_to_seg` 新原语:换 stub、保 TTL/LRU、不清 hfttl、不发事件 ——
  demote_in_place 的段侧孪生;**不走 store.del**)→ 目录登记。
- `apply_segmented`(replay)从 store.del 改为同一 `demote_to_seg`:
  replay 后冷行以 stub 存在,与运行时状态一致。删除语义照旧:后续 DEL 帧
  删 stub 即删行(段条目成垃圾)。

## 三、snapshot / AOF rewrite:stub 的持久形态

- snapshot 与 rewrite 遇 seg-backed Cold:**写 stub 记录**(新记录型:
  key + seg 目录引用 + tag),不 materialize(vlog 侧维持现状 materialize)。
  格式版本轴 bump,UPGRADING 记降级窗口。
- 重启真相集缝合:snapshot(含 stub)→ AOF replay(SEGMENTED 帧把重放出的
  热行相变回 stub;帧引用段缺失 = 具名拒启,R2c 语义不变)→ 段目录从
  manifest 装载。行数据全程不过 AOF/snapshot ✓。

## 四、gate

1. **KV 语义等价 e2e**:窗口表 vs 对照表(无窗),全命令面对照 ——
   GET/HGET/HGETALL/HMGET/HSCAN/EXISTS/TYPE/TTL/SCAN/DBSIZE/RANDOMKEY/
   HSET 合并/HSETNX/HINCRBY/HDEL/DEL,出窗后 + 复活 churn 后 byte 等。
2. **crash 矩阵**(R2c §五,crashgate 体裁):五步序每个间隙 SIGKILL,
   重启后 digest 与不 crash 基准等;帧/manifest 撕裂具名拒启。
3. 无 WINDOW 表 byte-identical(A5);KV/pubsub 赢线不碰。
4. 内存/持久化收益实测:出窗后 RSS 降(lx64 allocgate 体裁)+
   rewrite 产物尺寸降 + 重启加载时间降(冷行不重放数据)。

## 五、train 切分

1. **T-row-a**:ColdRef backing 判别 + `demote_to_seg` + 读写分流
   (serve/resolve/peek 三面)+ WindowRt row half(出窗产者,SEGMENTED
   帧首个真写方)+ KV 等价 e2e。
2. **T-row-b**:snapshot/rewrite 的 stub 记录型 + replay 缝合改造 +
   crash 矩阵 + lx64 实测三件套。
3. v-next:段 compact(dead 计数驱动)、stub 下盘(零残留)、
   claused 冷路径回接(T-scalar-b 与行段 payload 拍板合流)。

## 六、发散区(本轮)

1. **stub 即缓存热度信号**:touched 字节对行段照用 —— 冷行被二次读自动
   promote 回热,窗口语义自然获得"访问复活"(R2a 的访问窗假设免费回来了,
   不用单独设计)。
2. **段目录 mmap 化**:段 fence 表常驻内存,行段多时(千段)可 mmap 段文件
   降 page cache 双份 —— 记 v-next,等实测说话。
3. **vlog 退役路径**:行段稳定后,value-tier 的 vlog backing 对窗口表
   前缀可整体切到段 backing(一个 backing 少一套 compaction)——远期,
   不进 v5。
