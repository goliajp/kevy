# One case per [ids name] block. Fields:
#   run:    argv (shlex); $PORT $AUTH_PORT $SOCKET expand
#   setup:  repeatable; redis-cli -p $PORT <setup> after FLUSHALL
#   prepare: a shell command run in the CLI container before each run
#   cluster: a shape (bench/cligate_cluster.py: empty, 3, 3x1; legacy-3 etc. on
#           Redis 7.4.10 at 17010-17017) the nodes are rebuilt to before each
#           run; setup then goes through redis-cli -c to the group's first node
#   env:    K=V, repeatable
#   stdin:  C escapes (\n \r \t \\ \xHH), repeatable, concatenated
#   timeline: instead of stdin, steps over time separated by ` ; `: seconds to
#           wait, INT (SIGINT to the CLI), KILL, `$ <command>` beside it, or
#           bytes to type
#   screen: yes — compare what a terminal would show (bench/cligate_screen.py),
#           not stdout's bytes; each CLI gets its own empty history file
#   deviation + kevy.stdout / kevy.stderr / kevy.exit / kevy.stdout-contains
#           or kevy.stdout-replace (`old => new` over redis-cli's output)
#   mask: a regex whose matches in stdout become `#`; head: compare the first N
#           lines only (readings that change with time)
#   timeout: seconds each CLI may take (default 10)
#   reference: valkey-cli — compare with the pinned valkey-cli instead of redis-cli
#           (for what only valkey-cli has)
#   then: a shell command run in the CLI container after the CLI; its output is
#           appended to stdout (what the CLI left in a file)
#   compare: cluster — the order nodes are reported in is not the contract (the
#           entry node's table, filled in no fixed order after a reset)
#   compare: lines-any-order — line order is not the contract (a deviation in
#           order, or an order the server does not keep stable)
#           when kevy-cli is meant to differ (see deviations.txt)
