kevy 7.0.0 · Benchmarks

How fast, and where it isn't

One machine, 16 cores, loopback. Every figure is reproducible from bench/ in the repository. Read the last two rows before you decide anything — they are the ones where speed is not a reason to switch.

Four engines, one machine

50 connections, pipelines of 16, small values, each engine on 4 cores. Median of 15 windows (3 rounds of 5), counted from each server's own command counter over three-second windows rather than from the benchmark client's reported rate. A ≥ marks a number the load generator set: the engine does at least that, and such a competitor number gets no ratio.

LPUSH is 37% ahead of Redis 8.10.2, the narrowest row. At that margin your value sizes and key distribution weigh as much as the engine — if lists are your hot path, benchmark your own workload before you switch for speed.

What this does not tell you

It is loopback. There is no network here, and in a real deployment the network is usually what you are waiting for. An engine 2× faster at GET will not make your p99 2× better if most of your latency is the wire.

The values are small. At 64 KB per value the whole thing becomes bound by the kernel's TCP path and the gap closes to single digits. If you store large blobs, these numbers are not about you.

It is one machine. kevy has no cluster mode. If your problem is that a single machine is not enough, no number on this page helps.

localStorage beats kevy on a small synchronous read, and always will — it is a map in the page's own address space. kevy wins on the things that make localStorage a bad idea anyway: real TTLs, no 5 MB ceiling, byte values rather than strings, and writes that do not block the main thread.

Reproduce it

git clone https://github.com/goliajp/kevy && cd kevy
cargo build --release -p kevy

# four-way: kevy, Redis 8, valkey, Dragonfly
bash bench/arena.sh target/release/kevy

# two kevy builds side by side: the last release against this tree
bash bench/perfgate.sh compare last-release HEAD

Two scripts. Everything on this page comes out of them.
