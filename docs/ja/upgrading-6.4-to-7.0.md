# 6.4 から 7.0 へのアップグレード

要点：**プロトコル経由のクライアントはコードの変更不要、データディレクトリはそのまま開けます。** メジャーバージョンを上げたのは Rust 側のためです。ワークスペースの公開 API をすべて Rust API Guidelines に揃え、ほとんどのクレートでシグネチャが変わりました（[§10](#10-rust-api)）。また 6.x の間に予告していたとおり、kevy-cli のツールは `--kevy` の後ろでしか動かなくなりました。そのほかに確認が必要なものは以下のとおりです。組み込みストアがディレクトリに残しうる新しい二種類のファイル、実際の大きさで報告されるようになったインデックスのサイズ、フィールドが増えたいくつかの応答、そして Redis と同じ動きに直した四つの応答です（[§11](#11-変わった応答)）。

```toml
kevy-embedded = "7.0.0"
```

7.0.0 の中心は四つです。プロセスが強制終了されても、返った書き込みをすべて保つ組み込みストア（開くのも閉じるのも速くなりました）。値で一つのインデックスをシャードに分けるグローバルインデックス。以前の 4 分の 1 以下になったインデックスの行。そして暗号化したリンクです。ノード間のリンクと二つ目のクライアントポートがあり、どちらも設定しなければ無効です（[encrypted-links.md](encrypted-links.md)）。あわせて、3.0 の頃からデータを失っていた欠陥を直しました。[§9](#9-データを失っていた欠陥の修正) を見てください。

## 早見表

| こういう場合 | 変わること | § |
|---|---|---|
| サーバーを動かしている、またはプロトコル経由で kevy を使っている | バイナリを差し替えるだけ | — |
| 6.4 に戻す可能性がある | 先に 7.0 で一度開いてきちんと閉じる。グローバルインデックスは宣言し直す | 1 |
| インデックスに `MAXMEM` を設定している、または階層ストアの容量がインデックスの下限に近い | インデックスのサイズの読みが以前の 4 分の 1〜3 分の 1 になる。値が長い文字列だと大きくなることがある | 2 |
| `IDX.LIST` や `IDX.DESCRIBE` を位置で解析している | それぞれ `partitioning` の対が一つ増える | 3 |
| 組み込みストアの変更フィードや AOF を読んでいる | `MSET` がシャードごとに一つのフレームになる | 4 |
| うっかり同じポートでサーバーを二つ起動する | 二つ目は起動を拒否するようになる | 5 |
| `kevy_rt::Commands` を実装している | 既定実装つきのメソッドが三つ増える | 6 |
| `kevy_config` の構造体を構造体リテラルで作っている | 新しいフィールドを書くか、`..Default::default()` を使う | 7 |
| スクリプトで `kevy-cli doctor`、`export`、`sql compile` などを裸の単語で呼んでいる | ツールを `--kevy` の後ろに移す | 8 |

| インデックスの読み取りが触れるシャードを減らしたい | グローバルインデックスとして宣言する | [インデックス](indexes.md#グローバルインデックスpartition-global) |

## そのまま引き継がれるもの

どれも 6.4.0 のリリース版バイナリに対して実測しています。

- **バージョン混在のレプリケーション。** 6.4.0 のプライマリと 7.0.0 のレプリカは収束し、7.0.0 のプライマリと 6.4.0 のレプリカも収束します。ローリングアップグレードでは、レプリカを先に上げても、プライマリを先に上げても構いません。
- **データディレクトリは両方向に使える。** 6.4.0 が書いたディレクトリは 7.0.0 で開けます。7.0.0 が書き込んだあとに 6.4.0 で開き直しても、両方の世代がそろっています。文字列（value log に入る大きさの値を含む）、ハッシュ、リスト、セット、ソート済みセット、TTL です。例外の三つは §1 にあります。
- **バックアップはコピー。** コピーしたディレクトリは、元と同じデータを返します。

## 1. 6.4 に戻すとき、ディレクトリにありうるもの

以前は、プロセスが強制終了されると、ユーザー空間のバッファで待っていた書き込みが失われました。7.0 では追加が返った瞬間に、カーネルが持つメモリにあります。

- **Apple のプラットフォームでは** AOF そのものをマップし、末尾に事前確保した領域（4 MiB から倍々で 64 MiB まで）に追加をコピーします。ストアを開いている間はファイルがレコードより長く、残りはゼロです。きちんと閉じると切り詰められます。強制終了されたプロセスはゼロを残し、次に開いたときに取り除かれます。
- **それ以外では** 追加はまずステージングリング——小さなマップファイル `aof-<i>.aof.stage`（既定 4 MiB）——に入り、tick ごとに AOF へ移されます。強制終了されたプロセスがそこに残したものは、次に開いたときに再生されます。元のディレクトリでも、強制終了のあとにコピーしたディレクトリ（バックアップはそうして取ります）でも同じです。

6.4 はどちらも知りません。強制終了の直後のディレクトリを 6.4 で開くと、リングに残っていた書き込みを失います。Apple のプラットフォームでは書き込みはすべて残りますが、6.4 は末尾のゼロを壊れた末尾として報告し、隔離ファイルに移します。そのため、クラッシュや強制終了のあとは、6.4 に戻す前に 7.0 でディレクトリを一度開き、きちんと閉じてください。リングが空になり末尾が切り詰められて、6.4 がこれまでどおり読めるファイルになります。`Config::with_stage_ring(0)` と `Config::with_mapped_aof(false)` でこの二つを無効にでき、`AppendFsync::Always` はどちらも使いません。

ログにはほかに二つ新しいものがあり、サーバーでも組み込みストアでも同じです。ストリームのコンシューマーグループへの接触は内部の `XINTERNAL.CONSUMERSEEN` フレームとして記録され、6.4 はこれを読み飛ばします——その結果、`XGROUP CREATECONSUMER` だけで作られたコンシューマーを失います。また、グローバルインデックスを含むカタログは 6.4 が読めない sidecar 形式で書かれるため、それを渡された 6.4 のサーバーは、宣言し直すまでインデックスがない状態で起動します（テーブルがコンパイルしたパスも含めて）。

## 2. インデックスのサイズが実際どおりに報告される

`IDX.LIST`、`IDX.VERIFY`、`TABLE.VERIFY` の `bytes` は行あたり `値 + キー + 48` という見積もりでした。今はインデックスの葉が実際に持つバイト数を報告し、インデックス自体も以前よりずっと小さくなっています。キーが `row:<n>` のような `i64` インデックスは 1 行 16〜25 バイトと報告され（6.4 では 67 バイト）、実際の使用量は 6.4 の 4 分の 1 以下です。同じ数字がインデックスの `MAXMEM` と、階層ストアがインデックスのために取っておく領域に使われるため：

- 6.4 に合わせて決めた `MAXMEM` のインデックスは、`-INDEXOVERBUDGET` になるまでに数倍の行を持てます。
- 同じインデックスのもとで、階層ストアはより多くのデータをホットに保ちます。

値が長い文字列で、キーが数字でないインデックスは、行がランダムな順に書かれると葉が 60〜70% しか埋まらないため、6.4 の見積もりより大きく報告されることがあります。

上限ぎりぎりに決めた予算は、実データを入れたサンプルで `IDX.LIST` と照らして確かめてください。行あたりの式は [indexes.md](indexes.md#整合性とコストモデル) にあります。

## 3. `IDX.LIST` と `IDX.DESCRIBE` に対が一つずつ増える

- `IDX.LIST` の各行の末尾に `partitioning local|global` が付きます。グローバルインデックスには `partitions`、`max_entries`、`mean_entries` も加わります。
- `IDX.DESCRIBE` は `declaration` の直前に `partitioning` を示し、`declaration` は引き続き最後の対です。

キーで応答を読むクライアントには無視できる新しいキーが見えるだけですが、位置で数えるクライアントはそうはいきません。

## 4. 組み込みの `MSET` はシャードごとに一フレーム

組み込みストアはこれまで、`MSET` の各ペアをそれぞれのロックの下で設定し、それぞれ `SET` として記録していました。今は一つのシャードのペアを一つのロックの下で設定し、一つの `MSET` フレームとして記録するので、クラッシュしても各シャードの分は全部残るか全部残らないかのどちらかです。AOF、レプリカ、変更フィードには、キーごとの `SET` の代わりに `MSET` フレームが届きます。`SET` だけを扱うフィードの利用者は `MSET` も扱ってください。サーバーに対してはもともとそうする必要がありました。

## 5. 使用中のポートは拒否される

各シャードは `SO_REUSEPORT` で待ち受けるため、同じユーザーが同じポートで二つ目の kevy を起動すると、一つ目の待ち受けに加わっていました。両方が動き、それぞれが接続の一部を受け取るので、クライアントが読み返す側から書き込みが消えたように見えました。今はポートが使用中なら、起動は `Address already in use` で止まります。Redis と同じです。

## 6. ランタイムを組み込む Rust 利用者へ

`kevy_rt::Commands` に `take_ext_out`、`apply_ext`、`extension_targets` が加わりました。いずれも 6.4 の動作を保つ既定実装つきです。シャード間でメッセージを運び（書き込みはそれらが適用されてから応答します）、拡張の読み取りが必要なシャードを指定できるようにします。グローバルインデックスはこの上に作られています。

## 7. `kevy-config`：設定セクションの構造体にフィールドが増える

暗号化したリンクと、プロキシの後ろに置けるクラスタのために設定項目が増えました。設定項目はどれも公開フィールドです。

| 構造体 | 新しいフィールド |
|---|---|
| `Config` | `secure`（型は `SecureSection`：`private_key_file`、`listen_port`、`client_keys`、`cluster_port_base`、`announce_cluster_port_base`）|
| `ClusterSection` | `announce_ip`、`announce_port_base`、`secure`、`peer_keys` |
| `PeerEntry` | `repl_port_base` |
| `ReplicationSection` | `secure`、`upstream_key`、`replica_keys` |

すべてのフィールドを書いた構造体リテラルはコンパイルできなくなります。新しいフィールドを書くか、リテラルの末尾に `..Default::default()` を付けてください。上の表のうち既定値がないのは `PeerEntry` だけで、その新しいフィールドは `repl_port_base: None` と書けば以前と同じ動作です。`Config::load` や `Config::from_toml_str` で作った設定は変更不要です。新しい設定項目の既定値はどれも無効です。

## 8. kevy-cli：ツールは `--kevy` の後ろでだけ動く

kevy-cli 6.4 はツールを裸の単語で動かしていました（`kevy-cli doctor -p 6004`、`kevy-cli export …`、`kevy-cli sql compile f.sql --apply --url h:p`）。6.x の間は、実行のたびに `--kevy` での書き方を 1 行示していました。7.0 では裸の単語はサーバーのコマンドで、redis-cli と同じです。そのため古い書き方は `DOCTOR` をサーバーに送り、サーバーのエラーを表示します。ツールを `--kevy` の後ろに、接続オプションをその前に移してください。

```sh
kevy-cli -p 6004 --kevy doctor
kevy-cli -p 6004 --kevy sql compile schema.sql --apply   # --url h:p は -h h -p p に
kevy-cli -p 6379 --kevy diff 127.0.0.1:6380 user:        # 一つ目のサーバーはセッションの接続先
```

`digest <prefix>` と、ファイルを扱う形の `backup`/`restore` は `--kevy digest|backup|restore` です。古い書き方のためにあったライブラリ関数（`route_tool`、`run_doctor_cli`、`run_shadow_cli`、`run_lint_cli`、`run_backfill_keys_cli`）も削除しました。

## 9. データを失っていた欠陥の修正

以下はいずれも、エラーを出さずに書き込みや期限を失うことがありました。

- バックグラウンドの AOF 書き換え後の、ハッシュフィールド自身の TTL（3.0.0 から）
- トランザクションの途中でプロセスが死んだあとに書かれたデータが、その次の再起動で失われる（4.0.0 から）
- AOF 書き換えの最後のファイル入れ替えの瞬間に書かれたデータ（5.0.0 から）
- `BGSAVE` のあとに書かれたデータ。macOS と、io_uring を使わない Linux で（5.1.0 から）
- `GETEX key EX|PX` と条件つきの `HEXPIRE` の期限が、再起動で動いていた
- RESP3 での個数つき `SPOP` が、取り除いたメンバーなしで記録されていた
- 組み込みストアで TTL つきのキーが、期限を過ぎてもリーパーの 1 周期分（既定 100 ms、アプリが中断されている間はそれ以上）読めていた（1.11.0 から）
- サーバーで `TOPK` つきの `DESC` 実体化ビューを既存の行の上に作ると、シャードごとに最大ではなく最小の行が残っていた（3.0.0 から）
- 二つ以上のシャードを持つ組み込みレプリカのほとんどのキー。読み取りが探さないシャードに書かれていた

それぞれの詳細は [changelog](https://github.com/goliajp/kevy/blob/develop/CHANGELOG.md) にあります。


## 10. Rust API

ワークスペースの公開 Rust API はすべて [Rust API Guidelines](https://rust-lang.github.io/api-guidelines/) に揃えたので、kevy のクレートをライブラリとして使うコードはそのままではコンパイルできません。変更はいくつかの規則に従っていて、直す場所はコンパイラが一つずつ示します。

- `bool` の引数は意味を名前にした列挙型になりました。`store.copy(a, b, true)` は `store.copy(a, b, CopyMode::Replace)` です。
- 今後フィールドやバリアントが増えうる構造体と列挙型は `#[non_exhaustive]` です。構造体リテラルではなく `Default` か `with_*` で作り、`match` には `_` の腕を足します。
- 不変条件を持つ型はフィールドを非公開にし、同じ名前のメソッドで読みます。
- ある型を第一引数に取っていた関数は、その型のメソッドになりました。
- エラーは `String` ではなく、`std::error::Error` を実装した型です。プロトコルに出ていた文面は `as_wire()` か `to_wire()` で同じものが得られます。
- 変更フィードとレプリケーションで対になっていた (generation, offset) は一つの `FeedPosition` になりました。

組み込みストアでよくある書き換えは次のとおりです。

```rust
// 6.4
store.copy(b"src", b"dst", true)?;
store.linsert(b"l", true, b"c", b"b")?;
let (generation, offset) = store.changes_tail()?;
let batch = store.changes_since(generation, offset, 100, &[])?;
// 7.0
store.copy(b"src", b"dst", CopyMode::Replace)?;
store.linsert(b"l", InsertPosition::Before, b"c", b"b")?;
let tail: FeedPosition = store.changes_tail()?;
let batch = store.changes_since(tail, 100, &[])?;  // batch.next が次の位置
```

クレートごとの変更の一覧（旧 → 新）は [rust-api-7.0.md](../rust-api-7.0.md) にあります（英語）。

## 11. 変わった応答

変わった応答は四つです。最初の二つは Redis と同じ動きになり、残りの二つは誤っていた文面を取り除きました。

- `XRANGE`、`XREVRANGE` などストリーム ID を受け取るコマンドは、`5-` のようにハイフンの後ろが空の ID を Redis と同じく拒否します。6.4 は `5-<最大のシーケンス>` として読んでいました。
- `XAUTOCLAIM` のカーソルは次の保留エントリの ID で、最後まで見終わると `0-0` です。6.4 は最後に見た ID に 1 を足したものを返していました。一回の呼び出しで見るのは Redis と同じく最大 `COUNT × 10` 件で、6.4 は一覧をすべて見ていました。カーソルが `0-0` になるまで呼び続けるループはどちらでも動きます。
- 組み込みストアの `table_declare`、`table_replace`、`table_verify_report` の拒否は `-ERR ERR …` ではなく `-ERR …` になりました。
- 提供できない `TABLE.DECLARE … WINDOW` を拒否する文面から、途中の余分な空白 17 個を取り除きました。

## 入手

```toml
# Cargo.toml
kevy-embedded = "7.0.0"
```

```sh
npm install @goliapkg/kevy@7.0.0          # wasm
npm install @goliapkg/kevy-node@7.0.0     # Node ネイティブ
pip install kevy==7.0.0
go get github.com/goliajp/kevy-go/v7@v7.0.0
cargo install kevy --version 7.0.0        # サーバーバイナリ、ソースから
npm install -g @goliapkg/kevy-bin@7.0.0   # サーバーバイナリ、ビルド済み
```

Linux（x86-64、arm64）と macOS（arm64）向けのビルド済みサーバーバイナリは、それぞれ SHA-256 ファイルとともに [v7.0.0 release](https://github.com/goliajp/kevy/releases/tag/v7.0.0) にあります。`ghcr.io/goliajp/kevy:latest` を使うコンテナの利用者は次の pull で 7.0.0 になります。固定のタグは `ghcr.io/goliajp/kevy:7.0.0` です。
