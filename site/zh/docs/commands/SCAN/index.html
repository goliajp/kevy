SCAN

增量遍历键空间：每次调用只走一个 shard 的约 COUNT 个桶、返回下一个游标。

SCAN cursor [MATCH pattern] [COUNT count] [TYPE type]
分组
键空间扫描
起始版本
4.0.0
参数个数
至少 2 个
标志
readonly

复杂度

每次调用 O(COUNT) 个桶、完整一轮摊还 O(N) —— 反向二进制游标、rehash 安全（整轮期间一直存在的键至少返回一次、即使表在中途扩容）。

复杂度与兼容性是从 kevy 的实现里读出来的，不是抄 Redis 的文档。有几条确实不一样 —— 它们看起来像笔误，但不是。

与 Redis 的兼容性

有差异

有差异：游标编码为（shard、位置），只在签发它的服务器和 shard 数上有效 —— 与 Redis Cluster 游标按节点绑定是同一性质。MATCH 与 TYPE 在收集后过滤；COUNT 限定的是访问的桶数、不是返回的键数。
