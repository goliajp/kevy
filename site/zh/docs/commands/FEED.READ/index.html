命令 / 变更流 / FEED.READ

FEED.READ

从某个 shard 读取变更 feed 的帧，起点是给定的 generation / offset 游标。

FEED.READ shard generation offset [COUNT n] [PREFIX prefix ...]
分组
变更流
起始版本
3.0.0
参数个数
至少 4 个
标志
readonly extension

复杂度

只涉及单个 shard(shard 是参数，不是扇出)。在 backlog 里定位起始 offset 是 O(log B)，解码再重新编码是 O(count * 帧大小)。COUNT 默认 256，硬上限 4096。

复杂度与兼容性是从 kevy 的实现里读出来的，不是抄 Redis 的文档。有几条确实不一样 —— 它们看起来像笔误，但不是。

与 Redis 的兼容性

kevy 独有

kevy 独有：Redis 没有干净的对应物。键空间通知是发完即忘的，既没有游标也无法重放；Redis Stream 有游标，但它是一条你必须双写的流，而不是覆盖既有键空间的 feed；复制 backlog 才是这套东西的底座，但 Redis 只把它暴露给副本。kevy 刻意不做 broker：没有消费者组，没有服务端保存的位置，也没有跨 shard 的全局顺序。
