XAUTOCLAIM

从游标开始扫描并认领空闲的待处理条目。

XAUTOCLAIM key group consumer min-idle-time start [COUNT count] [JUSTID]
分组
流
起始版本
1.0.0
参数个数
至少 6 个
标志
write

复杂度

O(log P + K + COUNT log N)；空闲过滤跑在取数之前，因此一个全是新鲜条目的 PEL 会被完整走一遍。

复杂度与兼容性是从 kevy 的实现里读出来的，不是抄 Redis 的文档。有几条确实不一样 —— 它们看起来像笔误，但不是。

与 Redis 的兼容性

有差异

有差异：PEL 扫完之后返回的下一个游标是 last-claimed+1 而不是 0-0，所以循环到 0-0 才停的客户端要多一次往返。
