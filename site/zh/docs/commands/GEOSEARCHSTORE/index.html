GEOSEARCHSTORE

在 source 上执行 GEOSEARCH，并把命中结果写入 destination。

GEOSEARCHSTORE destination source FROMMEMBER member|FROMLONLAT longitude latitude BYRADIUS radius m|km|mi|ft|BYBOX width height m|km|mi|ft [ASC|DESC] [COUNT count [ANY]] [STOREDIST]
分组
地理空间
起始版本
1.0.0
参数个数
至少 5 个
标志
write

复杂度

搜索 O(log N + C)，外加在 destination 所属 shard 上重写它的 O(D + K log K)。

复杂度与兼容性是从 kevy 的实现里读出来的，不是抄 Redis 的文档。有几条确实不一样 —— 它们看起来像笔误，但不是。

与 Redis 的兼容性

有差异

有差异：STOREDIST 按查询所用的单位存距离（Redis 也是如此）；destination 写在它自己的 shard 上，因此 source 与 destination 可能落在不同的核心上，这次写入与那次读取之间不是原子的。
