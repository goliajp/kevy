4.0 版本

一个 Redis 兼容的引擎，
从零写起。

kevy 说的是 RESP 协议，实现了 184 条命令，而且没有任何第三方依赖——没有 hashmap crate，没有 hasher，没有异步运行时。33 个 crate，都是我们自己写的，都是 Rust。同一套引擎，可以撑起一台 16 核的服务器，可以嵌进一个 CLI，可以编译成 151 KB 的 WebAssembly，也可以在一颗连分配器都没有的 Cortex-M 单片机上启动。

在浏览器里试一下读文档看实测数字

$ kevy --port 6379

吞吐量，老老实实测出来的

同一台机器，16 核，走 loopback。五次运行取中位数，数字是从服务端自己的 total_commands_processed 里数出来的，取三秒稳态窗口内的增量——不是 redis-benchmark 打印的那个 rps。那个数被一个 250 ms 的定时器量化过，会给你一句听着很舒服的假话。

七条命令，三个对手，七战七胜。但请把最后两行读完。对 Redis 8，LPUSH 只领先 12%，ZADD 只领先 10%——差距薄到这个程度，决定胜负的是你的硬件、你的 value 大小、你的 key 分布，而不是我们。凡是薄成这样的行，我们一律用这个颜色标出来，因为一个只把自己好看的行印出来的基准页面，那叫广告。完整的测法，以及我们为了把它测对付出过什么。

零依赖是一条设计约束，不是一句吹嘘

哈希表是自己写的。hasher 是自己写的。RESP 解析器、B 树、arena 分配器、io_uring 绑定、事件循环、geohash、Lua 解释器——全都是自己写的，全都是 Rust，全都在这个仓库里。整个 kevy 附近唯一的 C，是内核不肯用别的方式暴露出来的那几个系统调用，在 kevy-sys 里手写成 unsafe extern "C"。libc 的那个 crate，我们不链接。

这不是洁癖。同一份代码之所以能同时编译成一台 16 核的服务端、一块 no_std 的单片机固件、一个 WebAssembly 模块，靠的正是这条约束——依赖树里没有任何东西能跳出来告诉我们这做不到。一个 crate 只要假定了分配器、假定了线程、假定了时钟，它就替你关上其中一扇门。

还有一个结果：供应链是可以读完的。33 个 crate，一个作者，一棵 cargo tree 一屏放得下。

kevy 不是什么

它不是集群。没有 gossip，没有 slot 迁移，没有 sentinel——复制和故障切换有，跨机器分片没有，而且是故意不做。没有 AUTH，也没有 TLS：请把它放在一个真正把这两件事做好的东西后面。有几条命令的行为和 Redis 不一样，有些还挺出人意料——SCAN 不是游标迭代器，ZRANK 是 O(N)，SPOP 不随机。每一条我们都写下来了，写在 Redis 自己的命令参考里没有的那一栏。

三十秒

三个入口。按你的数据待在哪里挑一个。

  1. 当服务端跑

    6379 端口上说 RESP。你的 redis-cli、你的客户端库、你现有的代码，一行都不用改。

    cargo install kevy
kevy --port 6379

  2. 放进你的 Rust 二进制

    没有 socket，没有进程。引擎就是一个 struct。

    kevy-embedded = "4.0"

let db = Db::open("data/")?;
db.set(b"k", b"v", None)?;
assert_eq!(db.get(b"k")?.as_deref(), Some(&b"v"[..]));

  3. 放进浏览器标签页

    gzip 之后 151 KB。数据落在 OPFS 上，刷新页面还在，发布订阅可以跨标签页。

    import { open } from "@goliajp/kevy";

const db = await open({ persist: { name: "app" } });
db.set("cart:u1", JSON.stringify(items), { ttlMs: 3600_000 });
