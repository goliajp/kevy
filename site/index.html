Architecture

Thread-per-core, shared nothing

Each shard owns its keyspace on its own core and its own reactor — io_uring on Linux, no cross-core locks on the hot path, no garbage collector to pause you at the worst moment.

Compatibility

Your client does not change

RESP2 and RESP3 on the wire, byte-for-byte differential-tested against valkey 9.1 in CI. Lua (EVAL), pub/sub, streams, transactions, keyspace notifications.

Availability

Replication and failover, not bolted on

Primary/replica with a real write log, quorum election with epoch fencing, planned FAILOVER, read-your-writes tokens, bounded staleness, and a static-scope cluster.

Put the store inside your program

consumer build · opt-level z · fat LTO

No daemon, no socket, no serialization: kevy-embedded is a Rust library your program calls directly. Bare metal

It boots on a microcontroller

Not a compile-check: CI builds a real firmware — hand-written vector table, bump allocator, panic handler, semihosting, because a zero-dependency engine cannot reach for cortex-m-rt — and boots it on a Cortex-M4 under QEMU on every push.

  • Firmware image 145 KB
  • Heap for an empty store 0 bytes — it allocates nothing until you write
  • 64 sensor keys 17.8 KB, TTL expires when the firmware advances its own clock
  • What runs there is the storage engine, not the full embedded façade — that needs std

CH 03

Store real data in the browser

headless Chrome · 100k keys · 16 B values

Not a wrapper over IndexedDB — the engine itself, compiled to WebAssembly, with a hand-written C ABI and no wasm-bindgen. Every operation runs in wasm linear memory; the write log is batched to OPFS off the hot path. Using IndexedDB to hold a log is not the same as using it as the engine — which is the difference the bars below measure.

Point writes · ops/sec · 100k keys

kevy (wasm)1,787,310
localStorage361,696 4.9×
IndexedDB9,479 189×

Scans move the same way: a pattern scan over 100k keys takes kevy 5.6 ms and IndexedDB 254 ms — 46×.

The axis kevy loses

localStorage reads a small value faster. It always will.

getItem is a native synchronous hash lookup with no boundary to cross. Every kevy read encodes the key, crosses into wasm, and copies the value back — and on a 16-byte value that crossing costs more than the lookup. Batching with mget() wins back ~1.5× and still loses: the per-key encode and per-value copy stay linear and cannot be amortized.

So: if your data is small, string-only and read-mostly, use localStorage. kevy earns its keep past ~5 MB, on writes, on scans, on TTL, and when a synchronous write blocking your tab is not acceptable.

CH 04

Give an agent memory it can search

kevy-mcp · stdio · zero-dependency JSON-RPC

Session state, episodic memory and a RAG corpus usually mean three systems. Here they are one store: vector ANN, full-text BM25 and secondary indexes over the same keyspace, with hybrid recall that fuses them — and an MCP server so an agent reaches it directly instead of through glue you maintain.

Recall

Four index kinds, one keyspace

  • Vector ANN (HNSW) — semantic recall over embeddings you supply
  • Full-text — inverted segments, BM25-ranked
  • Range / unique — ordinary secondary indexes
  • Hybrid — RRF fusion of vector × text, merged server-side

Reach

The agent talks to it directly

kevy-mcp is an MCP server over stdio, written under the same zero-dependency rule — its JSON-RPC is hand-rolled.

Deliberately five tools, not fifty: discover (the agent reads the verb table itself), read, explain, info, and write — which is opt-in. Commands go as an argv array, so the whole surface is reachable without a tool per verb.

Their schemas come from the same verb table that generates COMMAND DOCS and llms.txt — one source of truth, drift-checked in CI.

Shape

TTL is the memory policy

Session context expires on its own. Episodic memory carries both a vector and a time index. Chunks live beside the vectors they came from, so recall returns the text, not a row id you then have to go fetch.

Dependencies

0crates.io deps

The hash map, the allocator strategy, the RESP parser, the io_uring binding, the HNSW index, the Lua VM — all written here. 33 crates, all kevy-*. The only unsafe lives at the OS boundary; the store, the protocol and the persistence layers are #![forbid(unsafe_code)].

Verification

6platforms in CI

Byte-for-byte differential tests against valkey 9.1. Fuzzing on every trust boundary, miri on the unsafe stones, loom on the concurrency. A throughput ratchet that fails the build on regression. The MCU firmware is booted, not compiled.

Disclosure

1axis we lose

A spec sheet that prints only its wins is an advertisement. kevy reads a small value slower than localStorage and this page says so, in red, with the reason and the physics — because the number you are not told is the one that bites you in production.
